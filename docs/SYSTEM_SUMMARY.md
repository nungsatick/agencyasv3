# สรุประบบสนับสนุนการจัดทำบัญชีข้อมูลจังหวัด (เวอร์ชันใหม่)

เอกสารนี้สรุปทุกอย่างที่ทำไว้ในโปรเจกต์ `agencyasv3` เพื่อใช้เป็นข้อมูลตั้งต้นสำหรับเขียนคู่มือการใช้งานระบบ
ปรับปรุงล่าสุด: 16 ตุลาคม 2569 (ค.ศ. 2026)

> **สถานะ:** ระบบรันได้บนเครื่องพัฒนา (`http://localhost:3000`) ด้วยข้อมูลจริงครบ 76 จังหวัด มีชุดติดตั้งสำหรับเซิร์ฟเวอร์จริงแล้ว (ดู [DEPLOY.md](DEPLOY.md)) แต่ยังไม่ได้ติดตั้งบนเซิร์ฟเวอร์จริง
> รายการที่ยังไม่ได้ทำอยู่ในหัวข้อ [14. สิ่งที่ยังไม่ได้ทำ](#14-สิ่งที่ยังไม่ได้ทำ)
> งานที่ทำในแต่ละวันแบบย่อ ดูที่ [CHANGELOG.md](CHANGELOG.md)

## 1. ที่มาและเป้าหมาย

- เว็บเดิมคือ `https://agencyas.gdcatalog.go.th/{จังหวัด}` ของสำนักงานสถิติแห่งชาติ มี 76 จังหวัด (ไม่มีกรุงเทพฯ) เป็นระบบ PHP แม่แบบเดียวใช้ร่วมกัน
- แต่ละจังหวัดมี 3 หน้า: หน้าหลัก, `/docs` (เอกสารแยกปีงบประมาณ 2565–2570), `/utilization` (แดชบอร์ด Power BI)
- เป้าหมายของเว็บใหม่: หน้าตาทันสมัย ใช้ง่ายบนมือถือ มีระบบหลังบ้านจัดการเนื้อหา และย้ายข้อมูลเดิมมาครบ โดย**คง URL เดิมทั้งหมด**

### ปัญหาของเว็บเดิมที่เว็บใหม่แก้

| ปัญหาเดิม | สิ่งที่เว็บใหม่ทำ |
|---|---|
| ชื่อเอกสารพิมพ์อิสระ ไม่เป็นมาตรฐาน | เอกสารมี "ประเภท" และ "ประเด็น" ให้เลือกจากรายการ |
| หน้าเอกสารฝัง PDF ทุกไฟล์พร้อมกัน โหลดช้า | แสดงเป็นรายการ เปิดดูตัวอย่างทีละไฟล์เมื่อกด |
| เอกสาร 212 รายการไม่มีไฟล์จริง (แสดง PDF ตัวแทน) | นำเข้าเป็น "ร่าง" ไม่เผยแพร่ และบังคับแนบไฟล์ก่อนเผยแพร่ |
| ส่วนกลางไม่มีเครื่องมือดูข้ามจังหวัด | หลังบ้านมีหน้าภาพรวม 76 จังหวัด |
| สร้างคุกกี้ที่บันทึก IP ทุกครั้งที่เปิดหน้า โดยไม่แจ้ง | หน้าสาธารณะไม่สร้างคุกกี้ระบุตัวตน มีแถบขอความยินยอม |
| แก้หรือลบเอกสารแล้วไม่มีร่องรอย | มีประวัติเวอร์ชันไฟล์ ประวัติการแก้ไข และถังขยะ |

### 3.1 แผนภาพระบบ (เพิ่ม 15 ต.ค. 2569)

ไฟล์ .drawio แก้ต่อได้ด้วยโปรแกรม draw.io และมี .png / .svg สำหรับแนบเอกสาร สร้างจากสคริปต์ใน `docs/` จึงสร้างใหม่ได้เมื่อระบบเปลี่ยน

| แผนภาพ | ไฟล์ | เนื้อหา | สร้างด้วย |
|---|---|---|---|
| สถาปัตยกรรม | `agencyasv3-architecture.*` | ผู้ใช้ → nginx (HTTPS) → web container (Next.js 16 + Payload 3: หน้าเว็บสาธารณะ หลังบ้าน API) → PostgreSQL 17 และที่เก็บไฟล์, บริการภายนอก (CKAN, Power BI), ขั้นตอนนำขึ้นระบบ (Git → Docker build → Compose) และการสำรองข้อมูล (`backup.sh`) | `build_architecture.py` |
| ภาพรวมฐานข้อมูล | `agencyasv3-database.*` | ตารางหลักและความสัมพันธ์ (provinces, documents, dashboards, files, topics, document_types, users ฯลฯ) พร้อมกลุ่มตารางประกอบ (สิทธิ์ เนื้อหากลาง สถิติ hit_counts) | `build_database_overview.py` |

## 4. การเปิดระบบบนเครื่องพัฒนา

1. เปิด Docker Desktop
2. ที่โฟลเดอร์ `agencyasv3` รัน `docker compose up -d db`
3. ที่โฟลเดอร์ `web` รัน `npm run dev`
4. เปิด `http://localhost:3000/sisaket` (หน้าเว็บ) หรือ `http://localhost:3000/admin` (หลังบ้าน)

ข้อควรรู้:

- การติดตั้งแพ็กเกจ (`npm install`) บนเครื่องนี้ต้องข้ามไฟล์ตั้งค่า npm ระดับผู้ใช้ เพราะมีบรรทัด `allow-scripts` ที่ npm รุ่นนี้ไม่รับ: `npm_config_userconfig=<ไฟล์เปล่า> npm install`
- รหัสผ่านฐานข้อมูลใน `docker-compose.yml` ใช้สำหรับพัฒนาเท่านั้น ระบบจริงต้องตั้งใหม่
- ใส่ร่างนโยบายจาก `docs/policy/` เข้าระบบ: ที่โฟลเดอร์ `web` รัน `npx payload run scripts/load-policies.ts` (เขียนทับข้อความนโยบายที่มีอยู่ ไม่เปลี่ยนเลขเวอร์ชัน)
- ใส่ข้อมูลติดต่อสำนักงานสถิติจังหวัดจาก `migration/import/province_contacts.json`: ที่โฟลเดอร์ `web` รัน `npx payload run scripts/load-province-contacts.ts` (เขียนทับที่อยู่ โทรศัพท์ โทรสาร อีเมล ของทั้ง 76 จังหวัด)
- หลังนำเข้าข้อมูลเดิม (เครื่องใหม่หรือระบบจริง) ให้รันต่อตามลำดับ: `scripts/assign-dashboard-topics.ts` → `scripts/clear-resolved-review.ts` → `scripts/load-hero-images.ts` (ถ้าย้ายฐานข้อมูลจากเครื่องพัฒนาตาม DEPLOY.md ขั้น 4 ไม่ต้องรัน เพราะผลอยู่ในฐานข้อมูลแล้ว)
- นำเข้าข้อมูลเดิมใหม่ทั้งหมด: ที่โฟลเดอร์ `web` รัน `npx payload run scripts/import.ts` (รันซ้ำได้ ข้ามรายการที่มีแล้ว)

### 6.1 หน้าจังหวัด

- ส่วนหัว: ตราจังหวัด **ชื่อจังหวัดตัวใหญ่เด่นที่สุด** ชื่อระบบเป็นบรรทัดรองด้านบน และเมนู 4 รายการตามลำดับ: หน้าหลัก · สารสนเทศเพื่อการตัดสินใจ · เอกสาร · แผนงานและคู่มือ (ส่วนท้ายเรียงแบบเดียวกัน)
- แถบเด่น: ชื่อ "บัญชีข้อมูลจังหวัด..." ปุ่ม "ค้นหาชุดข้อมูลในระบบบัญชีข้อมูล" (ไป CKAN ของจังหวัด) และปุ่ม "ดูแดชบอร์ดจังหวัด"
  - มีภาพเด่น: ใช้เป็นพื้นหลัง มีสีธีมไล่ทับฝั่งที่มีข้อความ
  - ไม่มีภาพเด่น: พื้นสีธีมพร้อมตราจังหวัดขนาดใหญ่
- ตัวเลขสรุป 4 กล่อง: แดชบอร์ด เอกสาร จำนวนครั้งที่ประชุมของปีล่าสุด จำนวนปีที่มีข้อมูล ตัวเลข**นับขึ้นจาก 0** (ประมาณ 1.2 วินาที) เมื่อกล่องเลื่อนเข้ามาในจอ ไม่นับขึ้นถ้าเครื่องตั้งให้ลดการเคลื่อนไหว โปรแกรมอ่านหน้าจออ่านตัวเลขจริงเสมอ และกล่องกว้างเท่าตัวเลขจริงตั้งแต่แรก หน้าไม่ขยับ (`web/src/components/CountUp.tsx`)
- **สารสนเทศเพื่อการตัดสินใจ:** การ์ดแดชบอร์ด 4 ใบเต็มหนึ่งแถว ไม่ผูกกับปี (หัวข้อไม่มีปี) แสดงรายการที่**ปักหมุด**ก่อน แล้วเติมด้วยแดชบอร์ดใหม่ล่าสุดไปเก่าสุด ข้ามปีได้ การ์ดมีป้ายปีงบประมาณ และป้าย "ปักหมุด" สำหรับรายการที่ปักหมุด (วิธีปักหมุดดูหัวข้อ 8.6) กดการ์ดแล้วไปหน้าสารสนเทศเพื่อการตัดสินใจ และ**เปิดแดชบอร์ดนั้นให้ทันที** (ลิงก์แบบ `#d-{id}` นับเป็นการเข้าชม 1 ครั้ง)
- **เอกสารล่าสุด** (ปรับ 15 ต.ค. 2569): ตาราง 4 คอลัมน์ แสดง 5 รายการล่าสุด — ประเภท (ไอคอนสีตามหมวด) | ชื่อเอกสาร (พร้อมป้าย "ใหม่" ภายใน 30 วัน ป้ายประเด็น วันที่ประชุม) | ปีงบประมาณ | ไฟล์ (ภาพประเภทไฟล์ กดเปิดไฟล์ + ยอดเข้าชม/ดาวน์โหลด) แถวสลับสี กดชื่อแล้วไปหน้าเอกสาร (ปีของเอกสารนั้น) และเปิดตัวอย่างไฟล์ในแถวของเอกสารนั้นทันที เหมือนกดปุ่ม "ดูตัวอย่าง" (ลิงก์ `#preview-<id>`, `useOpenFromHash` ใน Interactive.tsx; เฉพาะ PDF/รูป) แถวนั้นมีพื้นสีและเลื่อนมาอยู่บนจอ ถ้าเป็น Template 1–3 ในการ์ดชุดข้อมูล การ์ดจะขยายเต็มแถวและมีปุ่ม "ปิดตัวอย่าง" (เอกสารที่ไม่มีไฟล์ใช้ลิงก์ `#item-<id>` ตามเดิม) บนมือถือแต่ละแถวเรียงเป็นบล็อก (ซ่อนคอลัมน์ปี) เรียงเอกสารที่ลงในระบบใหม่ก่อน แล้วต่อด้วยเอกสารจากเว็บเดิม ปีใหม่ไปเก่า

### 6.2 หน้าเอกสาร (ปรับหน้าตาใหม่ 12 ต.ค. 2569)

- **ปีงบประมาณ:** แถบปุ่มแบบ Segmented Control ขนาดเล็ก แสดงเฉพาะปีที่มีเอกสาร มีปุ่ม "ทั้งหมด" **ค่าเริ่มต้นคือ "ทั้งหมด"** (ปรับ 14 ต.ค. 2569 ทั้งหน้าเอกสาร สารสนเทศฯ และแผนงานและคู่มือ) **กด Ctrl (Mac: ⌘) ค้างแล้วคลิกเพื่อเลือกหลายปี** (ลิงก์แบบ `?year=2568,2569` หรือ `?year=all`) ตัวเลือกแบบเดียวกันนี้ใช้ในหน้าสารสนเทศฯ และหน้าแผนงานและคู่มือด้วย
- **ช่องค้นหา:** อยู่แถวเดียวกับปีงบประมาณ กรองรายการขณะพิมพ์ (ดูหัวข้อ 6.8)
- **แถบสรุปหมวด:** การ์ดเล็กของแต่ละหมวดที่มีเอกสารในปีนั้น มีไอคอน ชื่อหมวด และจำนวนรายการ กดแล้วเลื่อนไปที่หมวดนั้น หมวดที่ไม่มีเอกสารไม่แสดง (แทนปุ่มกรอง "ประเภท" แบบเดิม ลิงก์เก่าแบบ `?type=...` ยังเปิดได้แต่แสดงทุกหมวด)
- **แต่ละหมวดเป็นแผงแยกกันชัดเจน** (ปรับ 14 ต.ค. 2569): กรอบมีขอบสีตามโทนหมวด หัวแผงมีไอคอนในกรอบสี ชื่อหมวด และป้ายจำนวนรายการ ใช้ 4 โทนสี เมื่อเลือกหลายปี รายการในแต่ละหมวดแยกตามปี

| หมวด | โทนสี |
|---|---|
| การประชุมคณะกรรมการ, คำสั่งแต่งตั้ง | สีธีมของจังหวัด |
| บัญชีสถิติทางการ, แผนพัฒนาสถิติ, บัญชีข้อมูลดิจิทัล | เขียวอมฟ้า |
| ชุดข้อมูลตามประเด็น, ข้อกำหนดการวิเคราะห์ | ม่วงคราม |
| เอกสารอื่น | เทา |

- **การประชุม:** รวมเป็นการ์ดต่อครั้ง หัวการ์ดแสดง "ครั้งที่ x/ปี" วันที่ประชุม (ถ้ากรอกไว้) และจำนวนเอกสาร เอกสารที่ไม่ได้กรอกครั้งที่ไปอยู่ในการ์ด "ไม่ระบุครั้งที่" (แก้ได้โดยกรอกครั้งที่ในหลังบ้าน)
- **แต่ละรายการ:** ภาพประเภทไฟล์นำหน้า (PDF, XLS, XLSX, CSV, DOCX, PPT, JPG, PNG, ZIP, TXT, HTML จาก `web/public/filetypes/` ตามนามสกุลไฟล์ ชนิดอื่นแสดงเป็นตัวอักษร) ส่วนเอกสารที่เป็นลิงก์หรือไม่มีไฟล์ใช้ป้ายเดิม ชื่อเอกสาร คำอธิบาย (ไม่แสดงถ้าซ้ำกับชื่อ) ยอดเข้าชมและดาวน์โหลดใต้ชื่อ ด้านขวามีปุ่มไอคอนดาวน์โหลด และปุ่ม "ดูตัวอย่าง" (เปิด PDF หรือรูป**เต็มความกว้างใต้แถวของรายการนั้น** เฉพาะรายการที่กด)
- **หัวของแต่ละหมวด** (ปรับ 15 ต.ค. 2569): แถบสีทึบตามสีของหมวด (ประชุม = สีหลักจังหวัด, คำสั่ง/บัญชี = เขียวอมฟ้า, ชุดข้อมูล/ข้อกำหนด = ม่วง, อื่น ๆ = เทา) ตัวอักษรขาว ไอคอนในกรอบโปร่ง จำนวนรายการเป็นป้ายขาว แถบค้างอยู่บนจอขณะเลื่อนผ่านหมวดนั้น ลิงก์ที่พาไปเอกสาร (`#item-` / `#preview-`) หยุดใต้แถบพอดี
- **ชุดข้อมูลตามประเด็น:** การ์ดต่อประเด็นการพัฒนา มีแถบสีประเด็นที่ขอบบน Template 1-2-3 แสดงเป็นขั้นต่อกันพร้อมลิงก์เปิดไฟล์
  - **การจัดการ์ด** (ปรับ 15 ต.ค. 2569): เอกสารที่มีชื่อประเด็นการพัฒนาเดียวกันอยู่การ์ดเดียวกัน เอกสารจากเว็บเดิมที่ไม่มีชื่อประเด็นแยกการ์ดตาม "ประเด็น" (หมวด) ที่ระบุไว้ เอกสารที่ไม่ได้ระบุทั้งสองอย่างจะรวมกับชุดของประเด็นในปีนั้นเฉพาะเมื่อปีนั้นมีประเด็นเดียวและเป็น Template ที่ชุดนั้นยังขาด (บางชุดระบุประเด็นไว้แค่ Template 1) ไม่อย่างนั้นแยกเป็นการ์ด "ชุดข้อมูล" ของตัวเอง การ์ดที่ไม่มีชื่อประเด็นใช้หัวเรื่อง "ชุดข้อมูลประเด็น…" เดิมมี 20 การ์ดที่รวมสองประเด็นไว้ด้วยกัน ตอนนี้ไม่มีแล้ว
  - **ลิงก์ "ดูแดชบอร์ดประเด็นนี้"** (ปรับ 15 ต.ค. 2569): ไปหน้าสารสนเทศที่กรองปีและประเด็นไว้ ถ้าปีนั้นไม่มีแดชบอร์ดของประเด็น ลิงก์ไปปีที่ใกล้ที่สุดที่มี พร้อมบอกปี เช่น "(ปี 2568)" (ห่างเท่ากันเลือกปีใหม่กว่า) ไม่แสดงลิงก์เมื่อประเด็นนั้นไม่มีแดชบอร์ดเลย หรือการ์ดไม่มีประเด็น
  - ตัวเลขทั้งประเทศ (15 ต.ค. 2569): การ์ดที่มีลิงก์ปีเดียวกัน 106 ใบ ลิงก์ไปปีอื่น 11 ใบ ประเด็นที่ยังไม่มีแดชบอร์ด 4 ใบ การ์ดที่ไม่มีประเด็นประมาณ 189 ใบ
- **ข้อกำหนดการวิเคราะห์:** มีป้ายสีบอกประเด็นเหนือชื่อเอกสาร
- ลิงก์เดิมแบบ `#item-12345` ยังชี้ไปที่เอกสารนั้น
- ตรวจด้วยตาแล้วบนจอคอมพิวเตอร์ จอมือถือ และโหมดมืด

### 6.3 หน้าสารสนเทศเพื่อการตัดสินใจ

- เลือกปี (แถบปุ่มแบบเดียวกับหน้าเอกสาร มี "ทั้งหมด" และเลือกหลายปีด้วย Ctrl) และประเด็น (ปุ่มแคปซูลเล็กมีจุดสีประจำประเด็นและจำนวนในวงกลมเล็ก ประเด็นที่เลือกเปลี่ยนเป็นสีของประเด็นนั้น) แดชบอร์ดแสดงเป็นการ์ด มีภาพหน้าปก (ดูด้านล่าง) ป้ายประเด็น ชื่อ และยอดเข้าชม
- กดการ์ดแล้วจึงโหลดแดชบอร์ดด้านบน มีปุ่ม "เปิดเต็มหน้าจอ" และ "ปิด"
- **ถ้าผู้เข้าชมยังไม่อนุญาตเนื้อหาฝังจากภายนอก** จะเห็นกล่องอธิบายพร้อมปุ่ม "อนุญาตและแสดงแดชบอร์ด" และ "เปิดในแท็บใหม่" แทน

**ภาพหน้าปกแดชบอร์ด**
- การ์ดแดชบอร์ดทั้งหน้านี้และหน้าหลักของจังหวัดแสดงภาพหน้าแรกของแดชบอร์ด ถ้าไม่มีภาพจะแสดงไอคอนกราฟบนพื้นสีประเด็น
- ภาพได้จากสคริปต์ `web/scripts/capture-dashboards.ts` ซึ่งเปิดลิงก์แดชบอร์ดด้วย Chrome ในเครื่อง รอกราฟโหลด จับภาพหน้าแรก ตัดแถบเครื่องมือ Power BI ออก แล้วบันทึกเป็น "ภาพตัวอย่าง" ของแดชบอร์ด ภาพที่ระบบจับมีหมายเหตุ "ภาพหน้าปกที่ระบบจับจากหน้าแรกของแดชบอร์ดอัตโนมัติ"
- ลิงก์ที่ไม่มีกราฟ (ลิงก์เสียหรือต้องเข้าสู่ระบบ) ถูกข้ามและรายงานไว้ท้ายผล
- จังหวัดอัปโหลดภาพเองทับได้ที่ช่อง "ภาพตัวอย่าง" ของแดชบอร์ดในหลังบ้าน สคริปต์ไม่เขียนทับภาพที่คนอัปโหลด
- ภาพเป็นของวันที่จับ แดชบอร์ดที่แก้ทีหลังหรือเพิ่มใหม่ต้องรันสคริปต์ซ้ำ (`PROVINCE=<slug>` เพื่อทำจังหวัดเดียว, `REDO=1` เพื่อจับภาพที่ระบบเคยจับใหม่)
- การโหลดภาพหน้าปกไม่ถูกนับเป็นยอดดาวน์โหลด
- สถานะ (14 ต.ค. 2569): มีภาพหน้าปก **552 จาก 555** แดชบอร์ดที่มีลิงก์ สคริปต์ตัดพารามิเตอร์ `embedImagePlaceholder=true` (ทำให้ Power BI แสดงภาพนิ่งแทนรายงาน) และช่องว่างหน้าลิงก์ออกก่อนจับภาพแล้ว ที่เหลือ 3 รายการ Power BI แจ้ง "This content isn't available" คือลิงก์เสีย/ถูกยกเลิกการเผยแพร่ ต้องให้จังหวัดแก้ลิงก์: #223 ยโสธร (ข้าวอินทรีย์), #291 สุโขทัย (การบริหารจัดการขยะ), #330 สุราษฎร์ธานี (ยางพารา)

### 6.4 หน้าแผนงานและคู่มือ

- (ปรับ 17 ต.ค. 2569) สองกลุ่ม: "แผนการขับเคลื่อนบัญชีข้อมูลจังหวัด" (เลือกปีงบได้) และ **"คู่มือและสื่อสนับสนุน"** (เดิมชื่อ "เทคนิคการขึ้นชุดข้อมูล" ซึ่งเป็นชื่อหัวข้อหนึ่งในกลุ่ม) เมนูซ้ายแสดงกลุ่มพร้อมรายชื่อหัวข้อ กดไปหัวข้อได้ทันที ไฮไลต์หัวข้อที่อยู่บนจอ แถบหัวกลุ่มค้างบนจอขณะเลื่อน มือถือแสดงเฉพาะปุ่มกลุ่ม
- **การจัดการในหลังบ้าน (เมนู "เนื้อหากลาง", ส่วนกลางเท่านั้น):** แก้ครั้งเดียวมีผลทั้ง 76 จังหวัดทันทีที่บันทึก (ไม่มีขั้นร่าง) เลือกกลุ่ม ("แผนการขับเคลื่อนบัญชีข้อมูลจังหวัด" หรือ "คู่มือและสื่อสนับสนุน") ปีงบใช้กับกลุ่มแผนเท่านั้น: ใส่ปี = แสดงเมื่อผู้เข้าชมเลือกปีนั้น เว้นว่าง = แสดงทุกปีและอยู่ก่อนหัวข้อที่มีปี กลุ่มคู่มือไม่มีช่องปี แสดงทุกปีเสมอ เรียงตามลำดับการแสดง (เลขน้อยก่อน) เนื้อหาแต่ละหัวข้อ: ข้อความ, ไฟล์/ภาพ (ภาพแสดงในหน้า ไฟล์อื่นเป็นปุ่ม "เปิดเอกสาร"), รายการลิงก์มีเลขลำดับ (แต่ละข้อใส่ลิงก์หรือไฟล์), ที่มา รายการในหลังบ้านเรียงแบบเดียวกับหน้าเว็บ และมีปุ่มดูหัวข้อนั้นบนหน้าเว็บ
- **ฟอร์ม (ปรับ 17 ต.ค. 2569):** เรียงตามหน้าเว็บ (ข้อมูลหลัก → ข้อความ → ภาพและไฟล์ → รายการลิงก์และไฟล์ → ที่มา) ปีงบเป็นตัวเลือก (ค่าเริ่มต้นปีปัจจุบัน หรือ "ทุกปี") ภาพ/ไฟล์อัปโหลดในฟอร์มได้เลย แถวในรายการลิงก์แสดงชื่อและชนิด (ลิงก์/ไฟล์) พับไว้ตอนเปิด แถวที่ไม่มีทั้งลิงก์และไฟล์บันทึกไม่ได้ มีปุ่ม "ดูหัวข้อนี้บนเว็บ" รหัสในลิงก์และลำดับการแสดงระบบตั้งให้เอง (อยู่ในกล่อง "ตั้งค่าขั้นสูง") หัวข้อใหม่ต่อท้ายกลุ่ม เลื่อนลำดับด้วยปุ่ม ▲▼ ในรายการ (`POST /api/central-contents/:id/move` เรียงเลขใหม่ทั้งกลุ่ม)
- แผนการขับเคลื่อน: เลือกปี (แถบปุ่มแบบเดียวกับหน้าอื่น มี "ทั้งหมด" และเลือกหลายปีได้) แสดงอินโฟกราฟิกและคู่มือ PDF ของปีที่เลือก
- เทคนิคการขึ้นชุดข้อมูล: บทความสั้น 12 เรื่อง (PDF ที่เก็บในระบบ) และรายการลิงก์ไป gdhelppage.gdcatalog.go.th
- เนื้อหาชุดเดียวกันทุกจังหวัด ส่วนกลางแก้ที่เดียว

(เก็บไว้ที่ `migration/import/province_contacts.xlsx` แผ่น "ที่มา" บอกแหล่งและวันที่)

### 6.7 ตัวเลขการเข้าชมและดาวน์โหลด

**ยอดเข้าชมรวมของเว็บไม่แสดงบนหน้าเว็บแล้ว** (ย้ายไปแดชบอร์ดในหลังบ้าน ดูหัวข้อ 8.11) ระบบยังนับทุกครั้งที่เปิดหน้า เก็บเป็นยอดรวมรายวันต่อจังหวัดต่อหน้า

บนหน้าเว็บแสดงตัวเลขรายรายการ:

| ที่แสดง | ไอคอน | นับเมื่อ |
|---|---|---|
| เอกสารแต่ละรายการ (หน้าเอกสาร) | ดวงตา = เข้าชม | กด "ดูตัวอย่าง" ไฟล์ในหน้า หรือกด "เปิดลิงก์" ของเอกสารที่เป็นลิงก์ภายนอก |
| เอกสารแต่ละรายการ (หน้าเอกสาร) | บันทึก (แผ่นดิสก์) = ดาวน์โหลด | เปิดหรือดาวน์โหลดไฟล์ผ่านลิงก์ของไฟล์ รวมถึงเปิดจากลิงก์เดิมภายนอกเว็บ |
| การ์ดแดชบอร์ด (หน้าสารสนเทศเพื่อการตัดสินใจ) | ดวงตา = เข้าชม | กดเปิดแดชบอร์ด |
| หัวข้อในหน้าแผนงานและคู่มือ (เอกสารส่วนกลาง, เพิ่ม 17 ต.ค. 2569) | ดวงตา = เข้าชม | กดลิงก์ภายนอกในหัวข้อ (ตัวนับ `guide_link`) |
| หัวข้อในหน้าแผนงานและคู่มือ | บันทึก = ดาวน์โหลด | เปิดหรือดาวน์โหลดไฟล์ในหัวข้อ ภาพที่แสดงในหน้าไม่นับ ยอดรวมทุกจังหวัดเพราะเนื้อหาเหมือนกัน |

- ไม่นับเจ้าหน้าที่ที่เข้าสู่ระบบอยู่ และโปรแกรมอัตโนมัติ (bot) **ข้อควรรู้:** เบราว์เซอร์ที่ล็อกอินหลังบ้านค้างไว้จะไม่ถูกนับทุกหน้าของเว็บจังหวัด (ตัดสินจากคุกกี้เข้าสู่ระบบ) ถ้าจะทดสอบว่ายอดขยับ ให้ใช้หน้าต่างไม่ระบุตัวตน (Incognito) หรือเบราว์เซอร์อื่นที่ไม่ได้ล็อกอิน
- **การนับ "ดูตัวอย่าง"** (ปรับ 17 ต.ค. 2569): หน้าเว็บส่งสัญญาณนับ 1 ครั้งทุกครั้งที่เปิดตัวอย่าง (`POST /hit` ชนิด `file_view` พร้อมรหัสไฟล์) ส่วนการโหลดไฟล์ของตัวอย่าง (`?view=1`) ไม่นับแล้ว เดิมนับที่การโหลดไฟล์ ซึ่งเบราว์เซอร์เก็บไฟล์ไว้ 5 นาที การเปิดซ้ำในช่วงนั้นจึงไม่ถูกนับ การดาวน์โหลด/เปิดไฟล์ตรงยังนับที่การโหลดไฟล์เหมือนเดิม
- ตัวเลขบนหน้าเป็นยอด ณ ตอนโหลดหน้า เปิดตัวอย่างแล้วตัวเลขในแถวนั้นยังไม่ขยับจนกว่าจะโหลดหน้าใหม่ (การ์ดแดชบอร์ดบวกให้ทันทีเมื่อเปิด)
- เป็นยอดสะสมแบบไม่ระบุตัวตน ไม่เก็บ IP ไม่ใช้คุกกี้ การเปิดซ้ำของคนเดิมนับทุกครั้ง
- เริ่มนับตั้งแต่เปิดใช้คุณสมบัตินี้ ไม่มีตัวเลขย้อนหลังจากเว็บเดิม
- เอกสารที่ไม่มีไฟล์ (มีแต่ลิงก์) แสดงเฉพาะยอดเข้าชม

### 6.8 เครื่องมือบนหน้าเว็บ

| เครื่องมือ | ตำแหน่ง | การทำงาน |
|---|---|---|
| ปุ่ม ก− / ก+ | แถบเมนูด้านบน | ปรับขนาดตัวอักษร 3 ระดับ (ปกติ / ใหญ่ / ใหญ่มาก) ทั้งหน้าขยายตามเหมือนการซูมของเบราว์เซอร์ |
| ปุ่มรูปพระจันทร์ | แถบเมนูด้านบน | สลับโหมดมืด/สว่าง |
| ช่อง "ค้นหา" | หน้าเอกสาร แถวเดียวกับปีงบประมาณ (กล่องขอบมนแบบแคปซูล มีไอคอนแว่นขยายด้านซ้าย จำนวนที่พบแสดงเป็นบรรทัดเล็กใต้กล่อง) | กรองรายการขณะพิมพ์ จากชื่อ คำอธิบาย ประเด็น ประเภท และครั้งที่ประชุม ค้นในปีที่เลือกอยู่ หมวดหรือการ์ดที่ไม่มีรายการตรงจะถูกซ่อน |

| แถบเมนูด้านบน | ทุกหน้า | แถบสีของเมนูที่เลือกเลื่อนไปซ้ายหรือขวาไปยังเมนูที่กดทันที (0.35 วินาที) ไม่ต้องรอหน้าใหม่โหลด และเลื่อนกลับเมื่อกดย้อนกลับ ส่วนหัวทั้งแถบอยู่ใน layout ของจังหวัด จึงไม่ถูกวาดใหม่ตอนเปลี่ยนหน้า แถบสีไม่หายหรือกระโดด (ปรับ 15 ต.ค. 2569, `MainNav.tsx`) ผู้ที่ตั้งค่าเครื่องให้ลดการเคลื่อนไหวจะไม่เห็นการเลื่อน |
| การเลื่อนหน้า | ทุกหน้า | กดปุ่มหรือลิงก์ที่พาไปหมวดในหน้าเดียวกัน หน้าจะเลื่อนแบบนุ่มนวล (smooth scroll) |
| ปุ่ม "กลับด้านบน" | มุมล่างขวา | ปรากฏเมื่อเลื่อนลงมาเกินประมาณหนึ่งหน้าจอ กดแล้วเลื่อนกลับบนสุดแบบนุ่มนวล |

ผู้ใช้ที่ตั้งค่าระบบปฏิบัติการให้ลดการเคลื่อนไหว จะเลื่อนหน้าแบบทันทีแทน

ปุ่ม "คัดลอกลิงก์" ท้ายเอกสารแต่ละรายการถูกนำออกจากหน้าเว็บแล้ว (ตามที่ผู้รับผิดชอบโครงการขอ 12 ต.ค. 2569) ปุ่มคัดลอกลิงก์ไฟล์ในหลังบ้านยังมีอยู่

ขนาดตัวอักษรและโหมดมืดจำไว้ในเบราว์เซอร์ของผู้ใช้ (ไม่ส่งไปเซิร์ฟเวอร์ จัดเป็นการตั้งค่าที่จำเป็น ไม่ต้องขอความยินยอม)

**ความกว้างหน้า:** ทุกหน้า (แถบเมนู ภาพส่วนหัว เนื้อหา ส่วนท้าย) กว้างไม่เกิน 1200 พิกเซล และขอบซ้ายขวาตรงกันทุกหน้า หน้าหลักแสดงกล่องตัวเลข 4 กล่องและการ์ดแดชบอร์ด 4 ใบในแถวเดียวบนจอคอมพิวเตอร์

### 6.9 ป๊อปอัปประกาศ

- ขึ้นเมื่อเปิดหน้า ตามช่วงวันเวลา จังหวัด และหน้าที่ส่วนกลางกำหนด
- แสดงครั้งละ 1 รายการ (รายการที่ลำดับความสำคัญสูงสุด)
- ปิดได้ด้วยปุ่ม ✕ ปุ่ม "ปิด" ปุ่ม Esc หรือคลิกพื้นหลัง แถบล่างบาง ๆ มีช่อง "ไม่ต้องแสดงอีกวันนี้" (ติ๊กแล้วไม่แสดงอีกจนจบวัน วันถัดไปขึ้นใหม่ ไม่ว่าตั้งความถี่ไว้แบบใด) และปุ่มขนาดเล็ก
- **ปิดเองใน 10 วินาที:** แถบล่างแสดง "ปิดเองใน N วินาที" และเส้นสีบาง ๆ ที่หดลงตามเวลา เอาเมาส์ไปวางหรือแตะที่ป๊อปอัปจะหยุดนับชั่วคราว ("หยุดนับชั่วคราว") เมื่อปิดเองระบบจำแบบเดียวกับกดปิด (ตามความถี่ที่ตั้งไว้ และ "ไม่ต้องแสดงอีกวันนี้" ถ้าติ๊กไว้)
- ป๊อปอัปแสดงเฉพาะภาพ (ทั้งภาพ ไม่ตัดขอบ สูงไม่เกินจอ) และคำอธิบายตัวเล็กใต้ภาพถ้ามี ไม่แสดงคำว่า "ประกาศ" และหัวข้อ
- ความถี่: วันละครั้ง / ครั้งเดียว / ทุกครั้งที่เปิดหน้า (จำในเบราว์เซอร์ของผู้เข้าชม **แยกรายจังหวัด** ปิดหรือติ๊ก "ไม่ต้องแสดงอีกวันนี้" ที่จังหวัดหนึ่ง จังหวัดอื่นยังแสดงตามปกติ) แก้ไขประกาศแล้วบันทึก = นับเป็นฉบับใหม่ ผู้เข้าชมจะเห็นอีกครั้ง

### 6.10 โหมดไว้ทุกข์

- หน้าเว็บ**ทุกจังหวัด**เป็นโทนขาวดำ มีแถบและริบบิ้นสีดำที่มุมบน (ซ้ายเป็นค่าเริ่มต้น)
- ตั้งวันเริ่มและวันสิ้นสุดได้ พ้นวันสิ้นสุดระบบปิดเอง
- ตัวเลือก: คงสีของแดชบอร์ดไว้ และข้อความไว้อาลัยใต้แถบเมนู
- ไม่แก้ไฟล์ภาพ ปิดโหมดแล้วสีและธีมกลับเป็นปกติทันที

### 6.11 หน้านโยบาย

- `/policy/privacy` นโยบายการคุ้มครองข้อมูลส่วนบุคคล และ `/policy/cookies` นโยบายคุกกี้ เปิดจากลิงก์ในส่วนท้ายของทุกหน้า
- แสดงเลขเวอร์ชันนโยบาย และลิงก์ "กลับหน้าจังหวัด" เมื่อเปิดมาจากหน้าจังหวัด
- ข้อความมาจากหลังบ้าน (ดูหัวข้อ 8.9) บรรทัดแรกของข้อที่ขึ้นต้นด้วยเลขข้อ เช่น "1. ขอบเขตของนโยบาย" แสดงเป็น**หัวข้อตัวหนา** ชื่อเอกสารในย่อหน้าแรกก็เป็นตัวหนา
- **สถานะข้อความ:** บนเครื่องพัฒนาใส่ร่างไว้แล้วทั้งสองฉบับ (ร่างเมื่อ 12 ต.ค. 2569 จากไฟล์ใน `docs/policy/`) โดยใช้โครงหัวข้อตามประกาศนโยบายของระบบบัญชีข้อมูลภาครัฐ (GD Catalog) พ.ศ. 2564 แต่เขียนเนื้อหาให้ตรงกับข้อมูลที่ระบบนี้เก็บจริง **ร่างยังมีช่อง `[...]` ที่ต้องเติม และยังไม่ผ่านการตรวจของฝ่ายกฎหมาย** (ดูหัวข้อ 13)

## 7. ระบบผู้ใช้และการเข้าสู่ระบบ

### 7.1 บทบาท

| บทบาท | ทำอะไรได้ |
|---|---|
| ผู้ดูแลระบบส่วนกลาง | ทุกจังหวัด เนื้อหากลาง ประกาศ โหมดไว้ทุกข์ ตั้งค่าเว็บไซต์ ข้อมูลอ้างอิง (จังหวัด ประเด็น ประเภทเอกสาร) และผู้ใช้ทั้งหมด ลบถาวรได้ |
| ผู้ดูแลจังหวัด | เนื้อหาและการปรับแต่งของจังหวัดตัวเอง เพิ่ม/นำเข้า/ระงับ/ออกลิงก์/รีเซ็ต 2FA ให้**เจ้าหน้าที่ของจังหวัดตัวเอง** |
| เจ้าหน้าที่จังหวัด | เพิ่มและแก้เอกสาร แดชบอร์ด ของจังหวัดตัวเอง และแก้ข้อมูลสำนักงาน/ธีม/ภาพเด่นของจังหวัดตัวเอง |

### 7.2 การเข้าสู่ระบบ (2 ขั้น)

**หน้าตา** (ปรับ 15 ต.ค. 2569, `components/AuthShell.tsx`, `AuthFlow.tsx`, `app/(frontend)/login/login.css`): หน้าเข้าสู่ระบบ หน้าขอใช้บัญชี (`/request-account`) และหน้าเปิดใช้บัญชี (`/activate/…`) ใช้ธีมเดียวกัน แบ่งสองฝั่ง ฝั่งซ้ายเป็นภาพเมืองกลางคืนใต้ชั้นสีน้ำเงินเข้ม (`public/brand/login-city-full-v1.webp`) พร้อมตรา สสช./GDcatalog ข้อความ "เชื่อมโยงข้อมูลจังหวัด สู่การตัดสินใจที่ดีขึ้น" และชื่อระบบ ฝั่งขวาเป็นฟอร์ม หัวข้อฟอร์มคือชื่อระบบ "ระบบสนับสนุนการจัดทำบัญชีข้อมูลจังหวัด" บรรทัดเดียว (ขนาดตัวอักษรปรับตามความกว้างคอลัมน์ 17–25px) แถบขั้นตอน 1 บัญชีผู้ใช้ → 2 ยืนยันตัวตน ช่องกรอกมีไอคอน บรรทัด "ลืมรหัสผ่าน? ติดต่อผู้ดูแลจังหวัดเพื่อขอลิงก์ตั้งรหัสผ่านใหม่" และลิงก์ "ยังไม่มีบัญชี? ขอใช้บัญชีเจ้าหน้าที่" บนจอคอมหน้าสูงพอดีหนึ่งจอไม่ต้องเลื่อน (ทดสอบ 1280×600 ถึง 1920×1080) ฟอร์มที่ยาวกว่าจอเลื่อนเฉพาะคอลัมน์ขวา บนมือถือฝั่งซ้ายย่อเป็นแถบหัวสีเข้ม

1. ชื่อผู้ใช้ + รหัสผ่าน
2. รหัส 6 หลักจากแอปยืนยันตัวตน (Google Authenticator, Microsoft Authenticator) หรือรหัสสำรอง
   - (26 ต.ค. 2569) รหัส 6 หลักกรอกใน **6 ช่องแยก** จัดกึ่งกลาง (`components/CodeBoxes.tsx`) พิมพ์แล้วเลื่อนช่องเอง Backspace ย้อนช่อง วางรหัสทั้งชุดได้ และ**กรอกครบ 6 หลักแล้วส่งเองทันที** ไม่ต้องกดปุ่ม ใช้ทั้งหน้าเข้าสู่ระบบ และขั้นตั้งค่า 2FA ของหน้าเปิดใช้บัญชี / ตั้งรหัสผ่านใหม่ ถ้ารหัสผิด ช่องล้างและกลับไปช่องแรก รหัสสำรองยังเป็นช่องเดียวตามเดิม

- เข้าครั้งแรก: ระบบพาตั้งค่า 2FA (สแกน QR code → กรอกรหัสยืนยัน → รับ**รหัสสำรอง 10 ชุด** ซึ่งแสดงครั้งเดียว) ในแอปยืนยันตัวตนบัญชีจะชื่อ **"สนับสนุนบัญชีข้อมูล: <ชื่อผู้ใช้>"** (เปลี่ยนจาก "บัญชีข้อมูลจังหวัด" เมื่อ 15 ต.ค. 2569 บัญชีที่ตั้งค่าไว้ก่อนหน้ายังเห็นชื่อเดิมในแอป ใช้งานได้ปกติ)
- รหัสสำรองแต่ละชุดใช้ได้ครั้งเดียว
- ใส่รหัสผ่านผิด 5 ครั้ง หรือรหัส 2FA ผิด 5 ครั้ง: ล็อก 15 นาที
- เซสชันมีอายุสูงสุด 8 ชั่วโมงนับจากเข้าสู่ระบบ
- **ไม่ได้ใช้งาน 30 นาที ออกจากระบบอัตโนมัติ** (เพิ่ม 14 ต.ค. 2569): "ใช้งาน" คือคลิก พิมพ์ เลื่อนหน้า หรือแตะ ในแท็บหลังบ้านแท็บใดก็ได้ (ทุกแท็บนับร่วมกัน) ก่อนครบ 2 นาทีมีหน้าต่าง "ยังใช้งานอยู่หรือไม่?" นับถอยหลัง พร้อมปุ่ม "ใช้งานต่อ" / "ออกจากระบบ" ครบแล้วพาไปหน้าเข้าสู่ระบบพร้อมข้อความ "ออกจากระบบอัตโนมัติแล้ว เพราะไม่ได้ใช้งานเกิน 30 นาที" ต้องใส่รหัส 2FA ใหม่
  - เซิร์ฟเวอร์ตัดเองด้วย: หน้าจอรายงานการใช้งานจริงประมาณนาทีละครั้ง (`/api/users/activity`) เซสชันที่ไม่มีรายงานเกิน 30 นาทีถูกลบออกจากบัญชี คุกกี้นั้นใช้ไม่ได้อีก แม้มีหน้าจอเปิดค้างหรือมีคนคัดลอกคุกกี้ไป (`web/src/lib/idle.ts`, ตาราง `session_activity`)
  - บันทึกในประวัติการใช้งานว่า "ออกจากระบบอัตโนมัติ (ไม่ได้ใช้งาน 30 นาที)" 

### 7.3 วงจรชีวิตของบัญชี

- **ไม่มีการสมัครเอง** ผู้ดูแลเป็นผู้เพิ่มบัญชี
- บัญชีใหม่มีสถานะ "รอเปิดใช้บัญชี" ระบบออก**ลิงก์เปิดใช้บัญชี** (ใช้ครั้งเดียว อายุ 14 วัน) ให้ผู้ดูแลนำไปส่งให้เจ้าของบัญชีเอง
- เจ้าของบัญชีเปิดลิงก์ → ตั้งรหัสผ่านเอง (อย่างน้อย 8 ตัวอักษร ไม่มีชื่อผู้ใช้อยู่ข้างใน) → ตั้งค่า 2FA
- **ลืมรหัสผ่าน:** แจ้งผู้ดูแล ผู้ดูแลกด "ออกลิงก์ตั้งรหัสผ่านใหม่" (อายุ 24 ชั่วโมง)
- **โทรศัพท์หาย/เปลี่ยนเครื่อง:** ผู้ดูแลกด "รีเซ็ต 2FA" ผู้ใช้ตั้งค่าใหม่ตอนเข้าครั้งถัดไป
- **ย้ายออก:** ผู้ดูแลกด "ระงับบัญชี" (เข้าระบบไม่ได้ เซสชันที่ค้างหลุดทันที ประวัติการทำงานยังอยู่)
- **ไม่มีใครตั้งหรือเห็นรหัสผ่านของผู้อื่นได้** รวมถึงผู้ดูแลระบบ
- ระบบเก็บเฉพาะค่า hash ของลิงก์ ออกลิงก์ใหม่แล้วลิงก์เก่าใช้ไม่ได้ทันที

**ขอบเขตของบทบาทระดับจังหวัด (ผู้ดูแลจังหวัดและเจ้าหน้าที่จังหวัด)** ปรับ 14 ต.ค. 2569
- เห็นเฉพาะข้อมูลของจังหวัดตัวเองในทุกเมนู: เอกสาร แดชบอร์ด ถังขยะ (รวมรายการที่เผยแพร่แล้ว ซึ่งเดิมเห็นของทุกจังหวัด) ไฟล์ (ไฟล์ที่เอกสาร/แดชบอร์ด/ภาพเด่นของจังหวัดใช้ ไฟล์จากเว็บเดิมของจังหวัด และไฟล์ที่เจ้าหน้าที่ของจังหวัดอัปโหลด) ผู้ใช้ ประวัติการใช้งาน รายการรอตรวจ รายงานประเด็น สถิติการเข้าชม และจำนวนการใช้งานในหน้าประเด็น การจำกัดนี้มีผลกับ API ด้วยสำหรับเอกสารและแดชบอร์ด
- ไม่เห็นกลุ่มเมนู **"ส่วนกลาง"** (เนื้อหากลาง ประกาศ ตั้งค่าเว็บไซต์) และ **"ข้อมูลอ้างอิง"** (จังหวัด ประเด็น ประเภทเอกสาร) เปิดจากลิงก์ตรงก็ไม่ได้ (พากลับหน้าภาพรวม หรือแสดง "ไม่พบสิ่งใด") หน้าข้อมูลจังหวัดของตัวเองเข้าทางเมนู "ปรับแต่งหน้าเว็บ" ส่วนประเด็นและประเภทเอกสารยังเป็นตัวเลือกในฟอร์มตามปกติ
- ผู้เข้าชมหน้าเว็บสาธารณะยังเห็นเนื้อหาที่เผยแพร่ของทุกจังหวัดเหมือนเดิม

> ข้อควรระวังสำหรับคู่มือ: ใครได้ลิงก์เปิดใช้บัญชีไปก่อนก็ตั้งรหัสผ่านของบัญชีนั้นได้ ต้องส่งให้เจ้าของบัญชีโดยตรงทีละคน
> และระบบควรมีผู้ดูแลระบบส่วนกลางอย่างน้อย 2 คน เผื่อคนหนึ่งทำโทรศัพท์และรหัสสำรองหาย

## 8. ระบบหลังบ้าน (`/admin`)

หน้าแรกหลังบ้านเรียกว่า "ภาพรวม" ทั้งในเมนูและแถบนำทาง (เปลี่ยนคำเดิมของ Payload "แดชบอร์ด" ที่ซ้ำกับเมนูแดชบอร์ด) หน้าตา: เมนูด้านซ้ายพื้นสีเข้มมีไอคอน ฟอนต์ **Prompt** และสีชุดเดียวกับหน้าเว็บ ข้อความและปุ่มเป็นภาษาไทยทั้งหมด (ไม่มีตัวเลือกภาษาอื่น) เมนูของหน้าที่เปิดอยู่มีแถบไฮไลท์ค้างไว้ (ทุกเมนู รวมเมนูที่เพิ่มเอง และหน้าแก้ไขของรายการนั้น) รูปโปรไฟล์มุมขวาบนเป็นวงกลมสีพร้อมอักษรตัวแรกของชื่อ (ข้ามคำนำหน้าและสระหน้า เช่น "นางสาวเกศินี" → ก) แถบนำทาง (breadcrumb) ด้านบนแสดงชื่อหน้าปัจจุบันเสมอ และหัวเรื่องของทุกหน้ามีไอคอนเดียวกับเมนูนำหน้า (ขนาดใกล้เคียงตัวอักษรหัวเรื่อง) รายละเอียดของหน้ารายการ หน้าแก้ไข และคำอธิบายช่อง อยู่ในหัวข้อ 8.14–8.16

| ปรับแต่งหน้าเว็บ / ดูหน้าเว็บจังหวัด | บทบาทระดับจังหวัด | หน้าแก้ไขจังหวัดตัวเอง (ข้อมูลสำนักงาน ธีม ภาพเด่น) และหน้าเว็บจริง |
| สถิติการเข้าชม | ทุกคน (เห็นเฉพาะจังหวัดตัวเอง) | แดชบอร์ดการเข้าชมหน้าเว็บ (ดูหัวข้อ 8.11) |
| รายการรอตรวจ | ทุกคน (เห็นเฉพาะจังหวัดตัวเอง) | รายการจากเว็บเดิมที่ต้องให้คนตรวจ (ดูหัวข้อ 8.12) |
| ถังขยะ | ทุกคน (เห็นเฉพาะจังหวัดตัวเอง) | เอกสารและแดชบอร์ดที่ลบแล้ว กู้คืนได้ภายใน 30 วัน (ดูหัวข้อ 8.5) |
| บัญชีของฉัน | ทุกคน | อยู่ท้ายเมนู เหนือ "ออกจากระบบ" เปลี่ยนรหัสผ่าน ย้าย 2FA ไปโทรศัพท์เครื่องใหม่ ขอรหัสสำรองชุดใหม่ (ดูหัวข้อ 8.10) |
| เอกสาร / แดชบอร์ด / ไฟล์ | ทุกคน (เห็นเฉพาะจังหวัดตัวเอง) | จัดการเนื้อหา; **ไฟล์** (ปรับ 15 ต.ค. 2569, `lib/provinceFiles.ts`): บทบาทระดับจังหวัดแก้/แทนที่ได้เฉพาะไฟล์ของจังหวัดตัวเอง (แนบในเอกสาร/แดชบอร์ดของจังหวัด, ภาพเด่น, ไฟล์จากเว็บเดิมของจังหวัด, ไฟล์ที่เจ้าหน้าที่จังหวัดอัปโหลด และเวอร์ชันก่อนหน้าของไฟล์เหล่านี้) ทั้งทางหน้าจอและ API; อ่านได้เฉพาะไฟล์ฉบับปัจจุบัน (เหมือนผู้เข้าชมทั่วไป) และเวอร์ชันเก่าของจังหวัดตัวเอง; ลบได้เฉพาะส่วนกลาง |
| เนื้อหากลาง / ประกาศ / ตั้งค่าเว็บไซต์ (กลุ่ม "ส่วนกลาง") | **ส่วนกลางเท่านั้น** | เนื้อหาและการตั้งค่าที่มีผลทุกจังหวัด |
| จังหวัด / ประเด็น / ประเภทเอกสาร (กลุ่ม "ข้อมูลอ้างอิง") | **ส่วนกลางเท่านั้น** | ข้อมูลอ้างอิงที่ใช้ร่วมกันทุกจังหวัด |
| ผู้ใช้ / เพิ่มและนำเข้าผู้ใช้ / คำขอบัญชี / ประวัติการใช้งาน (กลุ่ม "ผู้ใช้งาน" เดิมชื่อ "ระบบ") | ตามสิทธิ์ (คำขอบัญชีและประวัติ: ส่วนกลาง + ผู้ดูแลจังหวัด) | รายชื่อและการจัดการบัญชี |
| ประวัติการใช้งาน | ส่วนกลาง (ทั้งหมด), ผู้ดูแลจังหวัด (จังหวัดตัวเอง) | ใครทำอะไร เมื่อไร (ดูหัวข้อ 8.13) |
| รายงานประเด็น | ทุกคน (เห็นเฉพาะจังหวัดตัวเอง) | ประเด็นทั้งหมดพร้อมจำนวนที่ใช้ และรายการที่ยังไม่มีประเด็น (ดูหัวข้อ 8.15) |
| ออกจากระบบ | ทุกคน | อยู่ท้ายสุดของเมนู ถัดจาก "บัญชีของฉัน" |

### 8.2 หน้าภาพรวม

- **ตัวกรองปีงบประมาณ** (ทั้งสองบทบาท): แถบปุ่มแบบหน้าเว็บ ค่าเริ่มต้น "ทั้งหมด" เลือกปีเดียว หรือกด Ctrl เลือกหลายปี กล่องตัวเลขและตารางนับตามปีที่เลือก (เอกสาร แดชบอร์ด ร่าง) ส่วน "รายการรอตรวจ" นับทุกปีเสมอ
- **ผู้ดูแลระบบส่วนกลาง:** กล่องตัวเลขรวม และตาราง 76 จังหวัด (เอกสารและแดชบอร์ดของปีล่าสุด ร่าง รอตรวจ มีผู้ดูแลจังหวัดแล้วหรือยัง) พร้อมปุ่มไอคอนไปรายการเอกสาร (📄) และหน้าเว็บของจังหวัดนั้น (👁 แท็บใหม่) แบบเดียวกับหน้ารายการอื่น
- **ปุ่ม "ส่งออกเป็น Excel"** (ทั้งสองบทบาท): ได้ไฟล์ 3 แผ่น คือ ภาพรวมรายจังหวัด, จำนวนเอกสารและแดชบอร์ดรายปีงบประมาณ, คำอธิบาย ส่วนกลางได้ครบ 76 จังหวัด บทบาทระดับจังหวัดได้เฉพาะจังหวัดตัวเอง
- **บทบาทระดับจังหวัด:** ตัวเลขของจังหวัดตัวเอง และปุ่มทางลัด เพิ่มเอกสาร / เพิ่มแดชบอร์ด / เอกสารทั้งหมด / ปรับแต่งหน้าเว็บ
- **การ์ดตัวเลข** (ปรับ 15 ต.ค. 2569): จำนวนคอลัมน์ตายตัว แถวเท่ากันทั้งตอนกางและย่อเมนู ตัวเลขชิดล่างการ์ด ผู้ดูแลส่วนกลาง 8 การ์ด (4 × 2): จังหวัดที่มีเอกสาร / แดชบอร์ด, เอกสาร, แดชบอร์ด, รายการรอตรวจ, จังหวัดที่ยังไม่มีผู้ดูแล, **บัญชีใกล้ถูกระงับ** (ไม่ได้ใช้งานเกิน 275 วัน), **คำขอบัญชีรอพิจารณา** ผู้ดูแลจังหวัดเห็นสองการ์ดหลังนี้เฉพาะของจังหวัดตัวเอง กดการ์ดแล้วไปรายการที่กรองไว้
- **หน้าตาการ์ด** (ปรับ 15 ต.ค. 2569, `Tile.tsx`): ไอคอนประจำการ์ด ชื่อสั้น ตัวเลขมีจุลภาค บรรทัดเล็กใต้ตัวเลขบอกช่วงที่นับ (เช่น "ทุกปี") หรือคำอธิบาย การ์ดจังหวัดที่มีเอกสาร/แดชบอร์ดแสดง 76 / 76 พร้อมแถบความคืบหน้า สีตามสถานะ: ฟ้า = จำนวน, ส้ม = มีเรื่องค้าง, เขียว = ไม่มีค้าง การ์ดที่กดได้มีลูกศรมุมขวาบนและยกขึ้นเมื่อชี้ (เอกสาร/แดชบอร์ด → รายการที่เผยแพร่, ร่าง → รายการร่าง, รอตรวจ → รายการรอตรวจ, จังหวัดที่ยังไม่มีผู้ดูแล → รายชื่อผู้ดูแลจังหวัด) มือถือแสดง 2 คอลัมน์

### 8.3 การลงเอกสาร

- **ช่อง "จังหวัด"** (ปรับ 16 ต.ค. 2569, `provinceField` ใน `access/index.ts`) ของเอกสารและแดชบอร์ด: ผู้ดูแลจังหวัดและเจ้าหน้าที่จังหวัดเห็นเฉพาะจังหวัดตัวเองในรายการให้เลือก รายการใหม่ตั้งเป็นจังหวัดตัวเองให้อัตโนมัติ และเซิร์ฟเวอร์ปฏิเสธจังหวัดอื่นทั้งตอนสร้างและตอนแก้ไข ("เลือกได้เฉพาะจังหวัดของคุณ") จึงเพิ่มรายการลงจังหวัดอื่นหรือย้ายรายการไปจังหวัดอื่นไม่ได้แม้เรียก API ตรง ผู้ดูแลระบบส่วนกลางเลือกได้ทุกจังหวัด
- **ช่อง "ปีงบประมาณ"** (ปรับ 16 ต.ค. 2569) ของเอกสารและแดชบอร์ดที่สร้างใหม่ ตั้งเป็นปีงบประมาณปัจจุบันให้ (นับตามวันที่ในประเทศไทย 1 ต.ค.–30 ก.ย. เช่น ตั้งแต่ 1 ต.ค. 2569 เป็น 2570) แก้ได้ รายการเดิมคงปีของตัวเอง (`lib/fiscalYear.ts`)

1. เมนู "เอกสาร" → "สร้างใหม่"
2. เลือกจังหวัด ปีงบประมาณ ประเภทเอกสาร
3. ชื่อเอกสาร: เมื่อเลือกประเภทแล้วระบบ**ตั้งชื่อมาตรฐานให้เอง** และปรับตามครั้งที่/ปี/ประเด็นที่กรอก พิมพ์ชื่อเองทับได้ ถ้าชื่อไม่ตรงกับชื่อมาตรฐานจะมีปุ่ม "ใช้ชื่อนี้" ให้กดกลับ
   - เอกสารการประชุม: `{ชื่อประเภท} ครั้งที่ {ครั้งที่}/{ปี}` เช่น "รายงานการประชุมคณะกรรมการระดับจังหวัด ครั้งที่ 2/2569"
   - ประเภทอื่น: `{ชื่อประเภท} {ประเด็นการพัฒนา} ปีงบประมาณ {ปี}`
   - ถ้าเว้นชื่อว่างแล้วบันทึก ระบบใส่ชื่อมาตรฐานให้
4. เอกสารการประชุม: กรอก "ครั้งที่" และวันที่ประชุม
5. ชุดข้อมูลและข้อกำหนดการวิเคราะห์: เลือก "ประเด็น" และกรอก "ประเด็นการพัฒนาของจังหวัด"
   - ช่องที่ประเภทนั้นไม่ใช้จะถูกซ่อน (เช่น คำสั่งแต่งตั้งไม่มีช่องครั้งที่และประเด็น) ยกเว้นช่องที่มีข้อมูลเดิมอยู่
6. กล่อง "ไฟล์แนบ" → "เลือกไฟล์เพื่อแนบ" (PDF, Excel, JPG, PNG เลือกได้หลายไฟล์)
7. "บันทึกร่าง" เพื่อเก็บเป็นร่าง หรือ "เผยแพร่การแก้ไข" เพื่อเผยแพร่

กติกา: **เผยแพร่ไม่ได้ถ้าไม่มีไฟล์แนบและไม่มีลิงก์ภายนอก** ระบบแจ้ง "แนบไฟล์หรือใส่ลิงก์ภายนอกก่อนเผยแพร่"

### 8.4 การแทนที่ไฟล์และประวัติไฟล์

- **หน้าไฟล์** (ปรับ 17 ต.ค. 2569): สร้างไฟล์ใหม่มีแค่กรอบอัปโหลด (เลือกไฟล์หรือลากวาง) กับคำอธิบาย ไม่มีปุ่ม "วาง URL" ชนิดที่รับ: PDF รูปภาพ Excel ขนาดไม่เกิน 50 MB ไฟล์ที่มีอยู่แล้วแสดงชื่อไฟล์ที่ผู้เข้าชมเห็น เหตุผลที่เปลี่ยนไฟล์ การ์ดประวัติเวอร์ชัน และข้อมูลทางเทคนิค (ลิงก์ของไฟล์ ค่าตรวจสอบ ที่อยู่ในเว็บเดิม) แบบพับไว้ อ่านอย่างเดียว

ในกล่อง "ไฟล์แนบ" ของหน้าแก้ไขเอกสาร แต่ละไฟล์มีปุ่ม:

| ปุ่ม | ผล |
|---|---|
| เปิดดู / คัดลอกลิงก์ | เปิดไฟล์ หรือคัดลอกลิงก์ถาวรของไฟล์ |
| แทนที่ด้วยไฟล์ใหม่ | เลือกไฟล์ใหม่ กรอก "เหตุผลที่แก้ไข" แล้วกดแทนที่ **มีผลทันที ไม่ต้องกดบันทึกเอกสาร** |
| ประวัติไฟล์ | รายการทุกเวอร์ชัน ผู้อัปโหลด วันเวลา เหตุผล พร้อม "เปิดดู" และ "กู้คืนเวอร์ชันนี้" |
| นำออกจากเอกสารนี้ | ถอดไฟล์ออกจากเอกสาร (ต้องกดบันทึกเอกสารจึงมีผล) |

- ไฟล์เดิมไม่ถูกลบ เก็บเป็นเวอร์ชันก่อนหน้า
- **ลิงก์ของไฟล์ไม่เปลี่ยน** และชี้ไฟล์ฉบับล่าสุดเสมอ
- การกู้คืนนับเป็นเวอร์ชันใหม่ ประวัติจึงไม่ขาดตอน
- เวอร์ชันเก่าเปิดดูได้เฉพาะผู้ที่เข้าสู่ระบบ

### 8.5 การลบและถังขยะ (ปรับใหม่ 14 ต.ค. 2569)

**ปุ่มลบอยู่ 2 ที่ (เอกสารและแดชบอร์ด):**
- หน้ารายการ: ปุ่มไอคอนถังขยะสีแดงท้ายแถว ต่อจาก "แก้ไข" และ "ดูบนเว็บ"
- หน้าแก้ไข: ปุ่ม "ย้ายไปถังขยะ" ข้างปุ่มบันทึก/เผยแพร่ (ลบเสร็จแล้วกลับไปหน้ารายการ)

ทุกครั้งมีกล่องยืนยันบอกชื่อรายการ และแจ้งว่ากู้คืนได้ 30 วัน รายการหายจากหน้าเว็บทันที

**เมนู "ถังขยะ"** (`/admin/trash`) รวมเอกสารและแดชบอร์ดไว้ที่เดียว แยกเป็นแท็บพร้อมจำนวน ค้นหาชื่อได้ (ส่วนกลางกรองจังหวัดได้) แต่ละแถวบอกวันเวลาที่ลบ และ "ลบถาวรใน N วัน" (ป้ายสีส้มเมื่อเหลือไม่เกิน 3 วัน) ปุ่ม "ถังขยะ (N)" ในหน้ารายการเอกสารและแดชบอร์ดก็พามาที่นี่

| ทำอะไร | ผู้ดูแลระบบส่วนกลาง | ผู้ดูแลจังหวัด / เจ้าหน้าที่จังหวัด |
|---|---|---|
| ย้ายไปถังขยะ | ทุกจังหวัด | เฉพาะจังหวัดตัวเอง |
| กู้คืน (กลับเป็นสถานะเดิม เช่น เผยแพร่แล้ว) | ทุกจังหวัด | เฉพาะจังหวัดตัวเอง |
| ลบถาวรทันที | ได้ | **ไม่ได้** (ปิดที่ฝั่งเซิร์ฟเวอร์ด้วย) |

- รายการที่อยู่ในถังขยะเกิน 30 วัน ระบบลบถาวรเอง (ตรวจทุก 6 ชั่วโมง) ไฟล์แนบของรายการนั้นยังอยู่ในเมนู "ไฟล์"
- การลบ กู้คืน และลบถาวร ถูกบันทึกในประวัติการใช้งาน
- การลบทีละหลายรายการ: ไม่มีในหน้ารายการ (เอาลิงก์ "รายการแบบขั้นสูง" ออกแล้ว 15 ต.ค. 2569) ลบทีละรายการ
- ถ้ารายการถูกกู้คืนหรือลบไปแล้วจากหน้าจออื่น ระบบแจ้งและโหลดหน้าใหม่ให้

### 8.6 การลงแดชบอร์ด

เมนู "แดชบอร์ด" → เลือกจังหวัด ปี ประเด็น กรอกชื่อ เลือกผู้ให้บริการ (Power BI เป็นค่าเริ่มต้น) วาง "ลิงก์สำหรับฝัง" → เผยแพร่

**ปักหมุดที่หน้าหลักของจังหวัด:** การ์ด "การแสดงบนเว็บ" ท้ายฟอร์มมีช่อง "ปักหมุดที่หน้าหลักของจังหวัด" ผู้ดูแลระบบส่วนกลางและบทบาทระดับจังหวัด (เฉพาะจังหวัดตัวเอง) ติ๊กได้ แดชบอร์ดที่ปักหมุดขึ้นก่อนในแถว 4 ใบของหน้าหลัก ถ้าปักหมุดเกิน 4 รายการ จะแสดงเพียง 4 รายการแรกตาม "ลำดับการแสดง" หน้ารายการแดชบอร์ดกรอง "เฉพาะที่ปักหมุด" ได้

### 8.7 ปรับแต่งหน้าเว็บจังหวัด

เมนู "ปรับแต่งหน้าเว็บ" (หรือ จังหวัด → เลือกจังหวัด):

- **ข้อมูลสำนักงาน:** ชื่อสำนักงาน ที่อยู่ โทรศัพท์ โทรสาร อีเมล เว็บไซต์ ลิงก์แผนที่ (แสดงในส่วนท้ายของหน้าเว็บ)
- **ธีมสี:** กดเลือกจาก 8 ชุด ตัวอย่างหน้าเว็บด้านล่างเปลี่ยนสีทันที มีผลจริงเมื่อกดบันทึก

  น้ำเงินทะเล (ค่าเริ่มต้น), เขียวป่า, ม่วงผ้าไหม, แดงครั่ง, ส้มอิฐ, น้ำตาลทอง, ชมพูบัว, เทาคราม
- **ภาพเด่นส่วนหัว:** อัปโหลดภาพ แนะนำ 2400 × 1000 พิกเซล (อัตราส่วน 12:5) ขั้นต่ำ 1680 × 700 ไฟล์ JPG ไม่เกิน 500 KB
  - วางจุดเด่นไว้กลางภาพ ฝั่งที่มีข้อความควรเป็นพื้นเรียบ ไม่ใส่ตัวหนังสือหรือโลโก้ในภาพ
- **จุดเด่นของภาพ:** เมื่อมีภาพแล้วจะมีกล่องให้กดบนภาพตรงส่วนที่ต้องเห็นเสมอ (หรือใช้ปุ่มลูกศร) พร้อมตัวอย่างการครอบภาพ 3 ขนาดจอ คือ คอมพิวเตอร์ แท็บเล็ต โทรศัพท์
- **ตำแหน่งข้อความบนภาพ:** ซ้ายหรือขวา
- **ที่มาของภาพ:** เช่น "ภาพสร้างด้วย AI" (แสดงในแถบล่างสุดของหน้า)

### 8.8 การจัดการผู้ใช้

- **เพิ่มทีละคน:** เมนู "เพิ่มและนำเข้าผู้ใช้" → กรอกชื่อผู้ใช้ (อังกฤษพิมพ์เล็ก) ชื่อ นามสกุล (ภาษาไทยได้ มีตัวอย่างในช่อง) บทบาท จังหวัด (ตำแหน่ง โทรศัพท์ อีเมล ไม่บังคับ) → "บันทึกและออกลิงก์" → คัดลอกลิงก์ส่งให้เจ้าของบัญชี
- **ช่องชื่อผู้ใช้** (เพิ่ม 15 ต.ค. 2569): ใต้ช่องมีชื่อแนะนำ 3 แบบจากอีเมลที่กรอก (ส่วนหน้า @, ชื่อจังหวัดนำหน้า เช่น `chyaphum.somchai`, และแบบมีเลขต่อท้าย) กดเพื่อใช้ได้ทันที ชื่อที่มีผู้ใช้แล้วขีดฆ่าและกดไม่ได้ ชื่อที่พิมพ์เองแสดงผลทันทีว่า "✓ ชื่อนี้ใช้ได้" หรือ "มีผู้ใช้ชื่อนี้แล้ว" (ตรวจผ่าน `GET /api/users/usernames` เฉพาะผู้ดูแลส่วนกลางและผู้ดูแลจังหวัด) ชื่อภาษาไทยไม่ใช้สร้างชื่อแนะนำเพราะแปลงเป็นอักษรอังกฤษให้ถูกไม่ได้ ช่องตำแหน่ง โทรศัพท์ อีเมล ไม่มีคำว่า "(ไม่บังคับ)" แล้ว (ยังเว้นว่างได้)
- **ชื่อ-นามสกุล (ภาษาอังกฤษ)** (เพิ่ม 15 ต.ค. 2569): ช่องใหม่ในฟอร์มขอใช้บัญชี (บังคับ) ฟอร์มเพิ่มผู้ใช้ (ไม่บังคับ) และหน้าแก้ไขผู้ใช้ เก็บในบัญชีผู้ใช้ (`nameEn`) และคำขอ ชื่อผู้ใช้แนะนำสร้างจากชื่อนี้ก่อน: Somjai Jaidee → `somjai.j`, `somjai.jaidee`, `<จังหวัด>.somjai` แล้วจึงจากอีเมล (migration `20261015_043645_name_en`)
- **กฎตรวจข้อมูลในช่องกรอก** (เพิ่ม 15 ต.ค. 2569, `lib/fieldRules.ts` ใช้ชุดเดียวกันทั้งฟอร์มและเซิร์ฟเวอร์): ตรวจเมื่อออกจากช่องและเมื่อกดส่ง ช่องที่ผิดมีขอบแดงและข้อความใต้ช่อง แก้ถูกแล้วข้อความหายทันที กดส่งแล้วเลื่อนไปช่องแรกที่ผิด
  - ชื่อ นามสกุล (ฟอร์มขอใช้บัญชี): ตัวอักษรไทยเท่านั้น เว้นวรรคระหว่างชื่อกับนามสกุล ในหลังบ้านและนำเข้า Excel รับไทยหรืออังกฤษ (ไม่มีตัวเลข) ไม่บังคับเว้นวรรค เพราะบัญชีผู้ดูแลจังหวัด 76 บัญชีเป็นชื่อสำนักงาน
  - ชื่อ-นามสกุลภาษาอังกฤษ: A–Z เว้นวรรค . ' - ต้องมีทั้งชื่อและนามสกุล
  - ตำแหน่ง หน่วยงาน: ไทย อังกฤษ ตัวเลข และ . , ( ) / - & ต้องมีตัวอักษร (ไม่ใช่ตัวเลขล้วน)
  - โทรศัพท์: ตัวเลข 9–10 หลักขึ้นต้นด้วย 0 (เว้นวรรค ขีด หรือ +66 ได้) เก็บเป็นตัวเลขล้วน
  - อีเมล: รูปแบบอีเมล อักษรอังกฤษ ไม่มีเว้นวรรค
  - ชื่อผู้ใช้: a–z 0–9 . - _ ขึ้นต้นด้วยตัวอักษรหรือตัวเลข ยาว 4–32
  - เหตุผล: ไม่เกิน 500 ตัวอักษร ห้าม < >
  - **การนำเข้าจาก Excel ใช้กฎชุดเดียวกัน** (15 ต.ค. 2569, `endpoints/importUsers.ts`): ตรวจทุกช่องของทุกแถว แถวที่ผิดแสดงเหตุผลรายช่อง เช่น "อีเมล: รูปแบบอีเมลไม่ถูกต้อง" และไม่ถูกสร้าง เบอร์โทรที่ Excel ตัดเลข 0 หน้าออก (เช่น 812345678) เติม 0 ให้ เก็บเป็นตัวเลขล้วน ไฟล์ต้นแบบเพิ่มคอลัมน์ H "ชื่อ-นามสกุล (ภาษาอังกฤษ)" (ไม่บังคับ ไว้ท้ายสุด ไฟล์แบบ 7 คอลัมน์เดิมยังนำเข้าได้) และแผ่น "คำอธิบาย" เขียนกฎของแต่ละช่อง (สร้างจาก `migration/build_user_template.py` คัดลอกไป `web/public/templates/`)
- **นำเข้าหลายคน:** ดูหัวข้อ 7.5
- **หน้าแก้ไขผู้ใช้** (เมนู "ผู้ใช้" → เลือกคน) มีปุ่ม: ออกลิงก์เปิดใช้บัญชี / ออกลิงก์ตั้งรหัสผ่านใหม่, รีเซ็ต 2FA, ระงับบัญชี, ยกเลิกการระงับ
- สถานะบัญชี: รอเปิดใช้บัญชี / ใช้งานอยู่ / ถูกระงับ แสดงเป็นป้ายสีในตารางรายชื่อผู้ใช้
- **ระงับอัตโนมัติ:** (ปรับจาก 180 เป็น **365 วัน** เมื่อ 15 ต.ค. 2569, `INACTIVE_DAYS` ใน `lib/maintenance.ts`) บัญชีที่ไม่ได้เข้าสู่ระบบเกิน 365 วัน (นับจากเข้าสู่ระบบครั้งล่าสุด หรือวันตั้งรหัสผ่านถ้ายังไม่เคยเข้า) ถูกระงับเอง พร้อมเหตุผล "ไม่ได้เข้าสู่ระบบเกิน 365 วัน" ผู้ดูแลกด "ยกเลิกการระงับ" ได้ **ไม่มีผลกับผู้ดูแลระบบส่วนกลาง** (กันไม่ให้ผู้ดูแลคนสุดท้ายถูกล็อก) บัญชีที่ยังไม่เปิดใช้ไม่ถูกนับ
- หน้าแก้ไขผู้ใช้แสดง "เข้าสู่ระบบล่าสุด"
- **ดูประวัติการใช้งานของผู้ใช้คนหนึ่ง** (เพิ่ม 15 ต.ค. 2569): ปุ่ม "ดูประวัติการใช้งาน" ในหน้าแก้ไขผู้ใช้ (ข้างปุ่มรีเซ็ต 2FA) และไอคอนนาฬิกาท้ายแถวในรายชื่อผู้ใช้ → หน้าประวัติการใช้งานกรอง `?user=<ชื่อผู้ใช้>` แสดงทั้งสิ่งที่ผู้ใช้นั้นทำ และการจัดการบัญชีนั้น (เพิ่มผู้ใช้ ออกลิงก์ รีเซ็ต 2FA ระงับ) มีลิงก์ "ดูของทุกคน" กลับ เห็นได้เฉพาะผู้ดูแลส่วนกลางและผู้ดูแลจังหวัด (จังหวัดตัวเอง)
- **หน้าภาพรวม** มีการ์ด "บัญชีใกล้ถูกระงับ" (ไม่ได้ใช้งานเกิน 275 วัน กดแล้วไปรายชื่อที่กรองไว้) และ "คำขอบัญชีรอพิจารณา" (กดแล้วไปหน้าคำขอบัญชี) สีส้มเมื่อมีรายการ ผู้ดูแลส่วนกลางเห็น 8 การ์ด (4 × 2 แถว) ผู้ดูแลจังหวัดเห็นของจังหวัดตัวเอง
- **คอลัมน์ "เข้าสู่ระบบล่าสุด" ในรายชื่อผู้ใช้** (เพิ่ม 15 ต.ค. 2569): ไม่เกิน 30 วัน แสดงวันที่; 31–274 วัน แสดงวันที่ + "N วันที่แล้ว"; **ตั้งแต่ 275 วัน** (เหลือ 90 วันก่อนถูกระงับ) ป้ายส้ม "ไม่ได้ใช้งาน N วัน" + "จะถูกระงับใน M วัน" (ผู้ดูแลส่วนกลางไม่มีข้อความนี้เพราะไม่ถูกระงับอัตโนมัติ); บัญชีที่ยังไม่เปิดใช้: "ยังไม่เคยเข้าสู่ระบบ · ลิงก์ใช้ได้ถึง …" หรือป้ายส้ม "ลิงก์หมดอายุ" (ให้ออกลิงก์ใหม่) ตัวกรองใหม่ "ใกล้ถูกระงับ (ไม่ได้ใช้งานเกิน 275 วัน)"
- **เจ้าของบัญชีรู้ชื่อผู้ใช้ของตัวเองจาก:** หน้าเปิดลิงก์เปิดใช้บัญชี/ตั้งรหัสผ่านใหม่ แสดง "ชื่อผู้ใช้ของคุณ" ตัวหนา และไฟล์ลิงก์ที่ดาวน์โหลดหลังนำเข้ามีคอลัมน์ชื่อผู้ใช้ ถ้าลืม ผู้ดูแลค้นได้จากเมนู "ผู้ใช้"
- ผู้ดูแลตั้งหรือเห็นรหัสผ่านของผู้อื่นไม่ได้ ช่องเปลี่ยนรหัสผ่านในหน้าแก้ไขผู้ใช้ถูกซ่อน เจ้าของบัญชีเปลี่ยนเองที่ "บัญชีของฉัน" หรือผ่านลิงก์ใช้ครั้งเดียว
- **คำขอบัญชี** (เพิ่ม 15 ต.ค. 2569; ไม่มีการสมัครเองแบบเปิด):
  - หน้าเข้าสู่ระบบมีลิงก์ "ขอใช้บัญชีเจ้าหน้าที่" → `/request-account` (ธีมเดียวกับหน้าเข้าสู่ระบบ) กรอกชื่อ นามสกุล จังหวัด ตำแหน่ง หน่วยงาน โทรศัพท์ **อีเมล** (ทั้งหมดบังคับ อีเมลใช้รับลิงก์เปิดใช้บัญชี) และเหตุผล (ไม่บังคับ) และติ๊กยินยอมให้ใช้ข้อมูล → "ส่งคำขอ" ไม่สร้างบัญชีจนกว่าจะอนุมัติ
  - กันสแปม (ปรับ 15 ต.ค. 2569):
    - ช่องลับดักโปรแกรมอัตโนมัติ และฟอร์มที่ส่งเร็วกว่า 3 วินาทีหลังเปิดหน้า: ตอบว่าสำเร็จแต่ไม่บันทึก
    - **ไม่เกิน 20 คำขอที่บันทึกสำเร็จ ต่อ IP ต่อ 1 ชั่วโมง** (ช่วงเลื่อน 60 นาที) ครั้งที่ข้อมูลผิดแล้วถูกปฏิเสธไม่นับ สำนักงานที่ใช้ IP เดียวกันจึงขอได้หลายคน ครั้งที่ 21 ขึ้นข้อความ "ส่งคำขอบ่อยเกินไป กรุณาลองใหม่ในอีก 1 ชั่วโมง"
    - IP อ่านจาก `X-Real-IP` ที่ nginx ใส่ให้ (ผู้ส่งปลอมไม่ได้) นับในหน่วยความจำของเซิร์ฟเวอร์ ไม่บันทึกลงฐานข้อมูล รีสตาร์ตแล้วเริ่มนับใหม่
    - เพดานนี้ทำงานเฉพาะบนระบบจริง (`NODE_ENV=production` ซึ่ง Dockerfile ตั้งไว้) **บนเครื่องทดสอบปิดไว้**
    - แต่ละจังหวัดมีคำขอรอพิจารณาได้ไม่เกิน 20 รายการ
  - เมนู "คำขอบัญชี" (กลุ่มผู้ใช้งาน) เห็นเฉพาะผู้ดูแลส่วนกลาง (ทุกจังหวัด) และผู้ดูแลจังหวัด (จังหวัดตัวเอง) เปิดมาแสดงคำขอที่รอพิจารณา กรองสถานะ/จังหวัด ค้นชื่อได้ เบอร์โทรกดโทรได้
  - **อนุมัติ** → เปิดหน้า "เพิ่มและนำเข้าผู้ใช้" ที่กรอกข้อมูลจากคำขอไว้ให้ ผู้อนุมัติตั้งชื่อผู้ใช้ ตรวจบทบาท/จังหวัด กด "บันทึกและออกลิงก์" คำขอเปลี่ยนเป็น "อนุมัติแล้ว" พร้อมลิงก์ไปบัญชีที่สร้าง ใต้กล่องลิงก์มี **ร่างอีเมล** (`EmailDraft.tsx`) ถึงอีเมลผู้ขอ: หัวเรื่อง, ชื่อผู้ใช้, ลิงก์และวันหมดอายุ, ขั้นตอนเปิดใช้บัญชี 4 ข้อ (ตั้งรหัสผ่าน, แอป 2FA, รหัสสำรอง, ที่อยู่หน้าเข้าสู่ระบบ) และลงท้าย "ขอแสดงความนับถือ / ผู้ดูแลระบบ" แก้ข้อความได้ แล้วกด "เปิดใน Gmail" / "เปิดใน Outlook" (หน้าเขียนอีเมลบนเว็บพร้อมข้อความ) / "โปรแกรมอีเมลในเครื่อง" หรือ "คัดลอกอีเมลทั้งหมด" ไปวางในอีเมลอื่น เช่น mail.go.th ตัวระบบไม่ส่งอีเมลเอง (ร่างนี้ขึ้นทุกครั้งที่เพิ่มผู้ใช้ที่มีอีเมล) **ไม่อนุมัติ** → ยืนยันแล้วเปลี่ยนสถานะ ทั้งสองแบบบันทึกผู้พิจารณาและเวลา และลงประวัติการใช้งาน (ส่งคำขอ / อนุมัติ / ไม่อนุมัติ)
  - คำขอที่ **ไม่อนุมัติ** มีปุ่มถังขยะท้ายแถว ลบถาวรได้ทันที (ยืนยันก่อน ลงประวัติการใช้งาน) ผู้ดูแลจังหวัดลบได้เฉพาะคำขอของจังหวัดตัวเอง คำขอที่รอพิจารณาหรืออนุมัติแล้วลบด้วยปุ่มนี้ไม่ได้
  - คำขอทุกสถานะถูกลบอัตโนมัติเมื่อครบ 30 วัน (`collections/AccountRequests.ts`, ต้อง migration `20261015_025612_account_requests` ตอนติดตั้ง)
- **ลบผู้ใช้** (แก้ 15 ต.ค. 2569): ก่อนลบบัญชี ระบบลบลิงก์ใช้ครั้งเดียวของบัญชีนั้นก่อน เดิมบัญชีที่เคยได้ลิงก์ลบไม่ได้ (ฐานข้อมูลปฏิเสธ)

### 8.9 งานของผู้ดูแลระบบส่วนกลาง

**ตั้งค่าเว็บไซต์** (เมนู "ตั้งค่าเว็บไซต์"):

- โหมดไว้ทุกข์: ติ๊กเปิด กำหนดวันเริ่ม/สิ้นสุด ตำแหน่งริบบิ้น ตัวเลือกขาวดำ + **ระดับความเป็นสีเทา 10–100%** (เพิ่ม 15 ต.ค. 2569, `mourning.grayLevel` ส่งเป็น CSS `--mourn-gray`; 100 = ขาวดำทั้งหมด) ริบบิ้น/คงสีแดชบอร์ด ข้อความไว้อาลัย → บันทึก ริบบิ้นลอยทับหน้าเว็บเป็นอีกชั้น ไม่ดันข้อความในส่วนหัว (บนมือถือย่อเหลือ 72%) ปุ่มเลื่อนกลับด้านบนเป็นสีเทาตามด้วย
- ส่วนท้ายของหน้าเว็บ: ข้อความลิขสิทธิ์ ข้อความเสริม เปิดปิดลิงก์เข้าสู่ระบบ/แผนที่ ลิงก์เพิ่มเติมในคอลัมน์เมนู
- นโยบาย: ช่อง "นโยบายความเป็นส่วนตัว" และ "นโยบายคุกกี้" แก้ข้อความแล้วกดบันทึก มีผลบนหน้าเว็บทันที แก้ได้เฉพาะผู้ดูแลระบบส่วนกลาง และถูกบันทึกในประวัติการใช้งาน
  - วิธีพิมพ์: เว้นบรรทัดว่างระหว่างข้อ บรรทัดแรกของข้อที่ขึ้นต้นด้วยเลขข้อ ("1. ...") จะเป็นหัวข้อตัวหนา หรือขึ้นต้นบรรทัดด้วย `#` แล้วเว้นวรรคเพื่อทำหัวข้อที่ไม่มีเลข การขึ้นบรรทัดใหม่ภายในข้อแสดงตามที่พิมพ์
  - "เลขเวอร์ชันนโยบาย": เพิ่มเลขเมื่อแก้สาระสำคัญ ระบบจะขอความยินยอมเรื่องคุกกี้จากผู้เข้าชมทุกคนใหม่ แก้คำผิดเล็กน้อยไม่ต้องเพิ่ม

**ประกาศป๊อปอัป** (เมนู "ประกาศ" → "สร้างใหม่"):

| ช่อง | หมายเหตุ |
|---|---|
| หัวข้อ | บังคับ ใช้เรียกประกาศในหลังบ้าน **ไม่แสดงบนป๊อปอัป** (โปรแกรมอ่านหน้าจอใช้เป็นชื่อป๊อปอัป) |
| คำอธิบาย / ภาพประกาศ | ไม่บังคับทีละช่อง แต่ประกาศที่เผยแพร่ต้องมีอย่างน้อยหนึ่งอย่าง **มีภาพอย่างเดียวก็เผยแพร่ได้** คำอธิบายแสดงเป็นตัวอักษรเล็กใต้ภาพ ภาพเลือกจากเครื่องด้วยปุ่ม "เลือกภาพจากเครื่อง" เห็นภาพตัวอย่างทันที เปลี่ยนหรือนำออกได้ (แนะนำแนวนอน 1240 × 520 พิกเซล แนวอื่นก็ได้) |
| ข้อความแทนภาพ | ไม่บังคับ สำหรับโปรแกรมอ่านหน้าจอ ไม่แสดงบนหน้าเว็บ เว้นว่างระบบใช้หัวข้อแทน |
| ข้อความบนปุ่ม / ลิงก์ของปุ่ม | ไม่บังคับ ถ้ามีลิงก์แต่ไม่มีข้อความบนปุ่ม การกดที่ภาพจะพาไปลิงก์นั้น |
| เริ่มแสดง / สิ้นสุด | เว้นสิ้นสุดว่าง = จนกว่าจะหยุดเอง |
| แสดงทุกจังหวัด | ถ้าไม่ติ๊ก ให้เลือกจังหวัด |
| แสดงที่หน้า | หน้าจังหวัดเท่านั้น / ทุกหน้า |
| ความถี่ | วันละครั้ง / ครั้งเดียว / ทุกครั้ง |
| ลำดับความสำคัญ | ค่ามากแสดงก่อน เมื่อช่วงเวลาซ้อนกัน |

กด "เผยแพร่" เพื่อเริ่มแสดง และ "หยุดเผยแพร่" เพื่อหยุดทันที

**เนื้อหากลาง:** แก้หัวข้อ เนื้อหา ไฟล์ และรายการลิงก์ของหน้า "แผนงานและคู่มือ" (หมวด: แผนการขับเคลื่อน / เทคนิคการขึ้นชุดข้อมูล)

**ข้อมูลอ้างอิง:** เพิ่มหรือแก้ ประเด็น (ดูหัวข้อ 8.15) และ ประเภทเอกสาร (กำหนดหัวข้อที่ประเภทนั้นไปอยู่บนหน้าเว็บ)

### 8.10 บัญชีของฉัน

เมนู "บัญชีของฉัน" (`/admin/my-account`) ทุกบัญชีใช้ได้ มี 3 ส่วน:

| ส่วน | ขั้นตอน | ผล |
|---|---|---|
| เปลี่ยนรหัสผ่าน | กรอกรหัสผ่านปัจจุบัน และรหัสผ่านใหม่ (อย่างน้อย 8 ตัวอักษร) → "เปลี่ยนรหัสผ่าน" | ออกจากระบบทุกอุปกรณ์ และพาไปหน้าเข้าสู่ระบบเพื่อเข้าใหม่ด้วยรหัสผ่านใหม่ |
| ย้ายการยืนยันตัวตนสองขั้นไปโทรศัพท์เครื่องใหม่ | กรอกรหัสผ่านเพื่อยืนยัน → "เริ่มตั้งค่าบนเครื่องใหม่" → สแกน QR ด้วยแอปบนเครื่องใหม่ → กรอกรหัส 6 หลัก → "ยืนยัน" | เครื่องเดิมใช้ไม่ได้อีก ได้รหัสสำรองชุดใหม่ |
| รหัสสำรอง | กรอกรหัสผ่านเพื่อยืนยัน → "ขอรหัสสำรองชุดใหม่" | รหัสสำรองชุดเดิมใช้ไม่ได้ทั้งหมด ชุดใหม่แสดงครั้งเดียว ให้คัดลอกหรือพิมพ์เก็บไว้ |

ถ้าทำโทรศัพท์หายและไม่มีรหัสสำรอง ต้องให้ผู้ดูแลกด "รีเซ็ต 2FA" ในหน้าแก้ไขผู้ใช้ แล้วตั้งค่าใหม่ตอนเข้าสู่ระบบครั้งถัดไป

### 8.11 แดชบอร์ดสถิติการเข้าชม

เมนู "สถิติการเข้าชม" (`/admin/visit-stats`)

- **ตัวกรองปีงบประมาณ** (เพิ่ม 15 ต.ค. 2569): "ทั้งหมด" (ค่าเริ่มต้น ใช้ปุ่ม 30 วัน / 90 วัน / 1 ปี เหมือนเดิม) หรือเลือกปี (Ctrl+คลิกเลือกหลายปี, `?year=2570`) ปีงบประมาณนับ 1 ต.ค.–30 ก.ย. เริ่มนับสถิติ 12 ต.ค. 2569 จึงเริ่มที่ปี 2570 เมื่อเลือกปี กราฟรายวันแสดงตั้งแต่ 1 ต.ค. ของปีนั้นถึงวันนี้ และ "แยกตามหน้า" กับคอลัมน์ในตารางรายจังหวัดใช้ช่วงปีที่เลือก การ์ดตัวเลขด้านบน (วันนี้/เดือนนี้/ปีงบประมาณนี้/ทั้งหมด) คงเดิม ตาราง "ไฟล์ที่ถูกเปิดมากที่สุด" เป็นยอดสะสมทุกปี (ตัวนับไฟล์ไม่ได้เก็บรายวัน) กดปุ่มช่วงวันจะกลับไปโหมดทั้งหมด

| ส่วน | แสดงอะไร |
|---|---|
| กล่องตัวเลข | วันนี้ / เดือนนี้ / ปีงบประมาณนี้ / ทั้งหมด และวันที่เริ่มนับ |
| แผนที่การเข้าชม (เฉพาะส่วนกลาง ดูทุกจังหวัด, เพิ่ม 15 ต.ค. 2569) | แผนที่ประเทศไทยตามขอบเขตจังหวัดจริง สีเข้มตามยอดในช่วงที่เลือก 5 ระดับ (ตัดตาม quintile) ไม่มีการเข้าชมเป็นสีเทา จังหวัดที่มีผู้เปิดหน้าเว็บใน 15 นาทีล่าสุดมีจุดสีส้มกระพริบและขอบสีส้ม ชี้เพื่อดูยอดและเวลาเข้าชมล่าสุด กดเพื่อดูรายจังหวัด จังหวัดเล็กรอบกรุงเทพฯ (นนทบุรี ปทุมธานี สมุทรปราการ สมุทรสาคร สมุทรสงคราม นครปฐม อยุธยา อ่างทอง สิงห์บุรี) มีกรอบขยายเหนืออ่าวไทย ข้างแผนที่มีรายการ "กำลังมีผู้เข้าชม" และ 10 อันดับ หน้ารีเฟรชข้อมูลเองทุก 1 นาทีขณะเปิดแท็บอยู่ "เวลาเข้าชมล่าสุด" มาจาก `updated_at` ของแถวยอดวันนี้ ไม่ได้เก็บข้อมูลเพิ่ม ขอบเขตจังหวัด: geoBoundaries gbOpen THA ADM1 (ปี 2017, จาก OpenStreetMap, สัญญาอนุญาต ODbL 1.0 ต้องแสดงที่มา ซึ่งแสดงใต้แผนที่แล้ว) แปลงด้วย `migration/build_thai_map.py` เป็น `web/src/lib/thaiMapPaths.ts` ไฟล์ต้นฉบับใน `migration/geo/` ไม่อยู่ใน git |
| การเข้าชมรายวัน | กราฟแท่งรายวัน เลือกช่วง 30 วัน / 90 วัน / 1 ปี ชี้ที่แท่งเพื่อดูวันที่และจำนวน |
| แยกตามหน้า | หน้าหลัก / เอกสาร / สารสนเทศเพื่อการตัดสินใจ / แผนงานและคู่มือ ในช่วงที่เลือก |
| รายจังหวัด (เฉพาะส่วนกลาง) | ตาราง 76 จังหวัด เรียงตามยอดในช่วงที่เลือก กด "ดูรายละเอียด" เพื่อดูเฉพาะจังหวัดนั้น |
| ไฟล์เอกสารที่ถูกเปิดมากที่สุด | 15 อันดับ พร้อมชื่อเอกสาร จังหวัด จำนวน "ดูตัวอย่าง" และ "ดาวน์โหลด" (แก้ 17 ต.ค. 2569: เดิมอ่านช่องที่ไม่เคยอัปเดต ตารางจึงว่างตลอด) |
| เอกสารส่วนกลาง (เฉพาะส่วนกลาง ดูทุกจังหวัด, เพิ่ม 17 ต.ค. 2569) | หัวข้อในหน้าแผนงานและคู่มือที่มีการเปิด: เข้าชม (เปิดลิงก์) และดาวน์โหลด (ไฟล์) รวมทุกจังหวัด รายการเนื้อหากลางในหลังบ้านก็มีคอลัมน์ "เข้าชม / ดาวน์โหลด" |

- ส่วนกลางเห็นทุกจังหวัดและเลือกดูรายจังหวัดได้ บทบาทระดับจังหวัดเห็นเฉพาะจังหวัดตัวเอง
- ไม่นับเจ้าหน้าที่ที่เข้าสู่ระบบและโปรแกรมอัตโนมัติ ไม่เก็บข้อมูลระบุตัวผู้เข้าชม

### 8.12 รายการรอตรวจ

เมนู "รายการรอตรวจ" (`/admin/review`) คือรายการที่ย้ายมาจากเว็บเดิมและต้องให้คนดู เช่น ไม่มีไฟล์จริง หรือจัดประเภทไม่ได้

- ส่วนกลาง: ตารางสรุปรายจังหวัด (จำนวนเอกสารและแดชบอร์ดที่รอตรวจ) กด "ดูรายการ" เพื่อเข้าไปดูของจังหวัดนั้น
- บทบาทระดับจังหวัด: เห็นรายการของจังหวัดตัวเองทันที
- แต่ละรายการบอก ปี ชนิด ชื่อ (และชื่อในเว็บเดิมถ้าต่างกัน) สถานะ และสิ่งที่ควรตรวจ กดชื่อเพื่อเปิดแก้ไข
- เมื่อตรวจแล้ว เอาเครื่องหมาย "รอตรวจ" ออกในกล่อง "ข้อมูลจากเว็บเดิม" ของรายการนั้นแล้วบันทึก

### 8.13 ประวัติการใช้งาน

เมนู "ประวัติการใช้งาน" (กลุ่ม "ผู้ใช้งาน") เป็นรายการอ่านอย่างเดียว ไม่มีใครเพิ่ม แก้ หรือลบได้ ค้นหาด้วยชื่อผู้ใช้หรือชื่อรายการ และกรองตามการกระทำหรือจังหวัดได้

| กลุ่ม | สิ่งที่บันทึก |
|---|---|
| การเข้าสู่ระบบ | เข้าสู่ระบบสำเร็จ, กรอกรหัสผิดจนบัญชีถูกล็อก |
| เนื้อหา (เอกสาร แดชบอร์ด เนื้อหากลาง ประกาศ จังหวัด ตั้งค่าเว็บไซต์) | สร้าง, แก้ไข, เผยแพร่, หยุดเผยแพร่, ย้ายไปถังขยะ, กู้คืน, ลบถาวร |
| ไฟล์ | อัปโหลดไฟล์, แทนที่ไฟล์ |
| ผู้ใช้ | เพิ่มผู้ใช้, ออกลิงก์ใช้ครั้งเดียว, รีเซ็ต 2FA, ระงับ, ยกเลิกการระงับ, เปลี่ยนรหัสผ่าน |
| ระบบทำเอง | ระงับอัตโนมัติ (365 วัน), ลบถาวรจากถังขยะ (30 วัน) แสดงผู้ใช้เป็น "ระบบ" |

แต่ละบรรทัดมี วันเวลา ผู้ใช้ การกระทำ ส่วนของระบบ ชื่อรายการ และจังหวัด ไม่บันทึกเนื้อหาที่เปลี่ยน (ดูได้จากแท็บเวอร์ชันของเอกสาร) และไม่บันทึก IP
ผู้ดูแลจังหวัดเห็นเฉพาะบรรทัดของจังหวัดตัวเอง เจ้าหน้าที่จังหวัดไม่เห็นเมนูนี้

### 8.14 หน้ารายการ (ปรับใหม่ 14 ต.ค. 2569)

ทุกเมนูที่เป็นรายการ (เอกสาร แดชบอร์ด ไฟล์ เนื้อหากลาง ประกาศ จังหวัด ประเด็น ประเภทเอกสาร ผู้ใช้ ประวัติการใช้งาน) ใช้หน้าตาแบบเดียวกัน ที่อยู่เป็น `/admin/{ชื่อรายการ}` เช่น `/admin/documents`

| ส่วน | รายละเอียด |
|---|---|
| ส่วนหัว | ชื่อหน้า คำอธิบายสั้น และปุ่ม (เช่น "เพิ่มเอกสาร", "ถังขยะ") |
| แถบตัวกรอง | ช่องค้นหา (ทรงแคปซูลมีไอคอนแว่นขยายแบบเดียวกับหน้าเว็บ ความสูงเผื่อสระบน-ล่างภาษาไทยไม่ให้ถูกตัด ข้อความแนะนำที่ยาวเกินกล่องจบด้วย "…" และดูเต็มได้เมื่อชี้เมาส์ ค้นหลังหยุดพิมพ์ครู่หนึ่ง) รายการเลือกแบบธรรมดา (เช่น จังหวัด ปีงบประมาณ ประเภท ประเด็น สถานะ) และช่องติ๊ก (เช่น "เฉพาะรายการรอตรวจ", "เฉพาะที่ปักหมุด", "เฉพาะที่ยังไม่ตั้งค่า 2FA") มีปุ่ม "ล้างตัวกรอง" เมื่อมีตัวกรองอยู่ ตัวกรองเก็บไว้ในลิงก์ จึงบุ๊กมาร์กหรือส่งต่อได้ |
| แถบจำนวน | "แสดง 1–25 จาก N รายการ" |
| เรียงข้อมูล | **กดหัวคอลัมน์**เพื่อเรียงจากน้อยไปมาก (ก–ฮ, เก่าไปใหม่) กดซ้ำเพื่อเรียงจากมากไปน้อย หัวคอลัมน์ที่ใช้เรียงอยู่มีลูกศร ▲/▼ คอลัมน์อื่นที่เรียงได้มี ↕ จาง ๆ (คอลัมน์จังหวัดเรียงตามชื่อจังหวัด) ถ้ายังไม่กด ใช้ลำดับตั้งต้นของแต่ละหน้า เช่น แก้ไขล่าสุดก่อน ตารางสรุปในหน้าภาพรวม สถิติการเข้าชม รายงานประเด็น และรายการรอตรวจ ก็กดหัวตารางเรียงได้แบบเดียวกัน (เรียงในเบราว์เซอร์ เพราะแสดงครบในหน้าเดียว) |
| ช่องเลือกภาพ (ภาพประกาศ ภาพเด่นจังหวัด ภาพหน้าปกแดชบอร์ด) | (ปรับ 15 ต.ค. 2569, `ImageField.tsx`) ใส่ภาพได้ 3 ทาง: ปุ่ม "เลือกภาพจากเครื่อง", ปุ่ม "วางจากคลิปบอร์ด" (เบราว์เซอร์อาจขออนุญาตอ่านคลิปบอร์ดครั้งแรก) หรือคลิกในกรอบแล้วกด Ctrl+V และลากไฟล์ภาพมาวางในกรอบ ภาพที่วางตั้งชื่อเป็น `paste-ปีเดือนวัน-เวลา.png` ถ้าคลิปบอร์ดไม่มีภาพจะมีข้อความบอก เมื่อมีภาพแล้ววางภาพใหม่ทับได้ |
| การ์ดตัวเลขหน้าภาพรวม | (ปรับ 15 ต.ค. 2569) จำนวนคอลัมน์ตายตัว ไม่ขึ้นกับความกว้าง: 6 ใบ = 3 คอลัมน์ (6 คอลัมน์เมื่อจอกว้าง ≥1500px), 4 ใบ = 4 คอลัมน์, จอแคบ 2 / 1 คอลัมน์ แถวจึงเท่ากันเสมอทั้งตอนกางและย่อเมนู ตัวเลขชิดล่างการ์ดให้ตรงแนวกันแม้หัวข้อยาว 2 บรรทัด |
| แถบนำทาง (breadcrumb) | (ปรับ 15 ต.ค. 2569) แคปซูลสีขาวที่แถบบน: ปุ่มกลมรูปบ้าน (ไปภาพรวม) › ขั้นระหว่างทางเป็นลิงก์พร้อมไอคอนเมนู › หน้าปัจจุบันเป็นชิปสีฟ้าอ่อนตัวหนาพร้อมไอคอนเมนู (ไอคอนใส่โดย `NavHighlight.tsx`) ชื่อยาวตัดเป็น "…" บนมือถือซ่อนขั้นระหว่างทาง ตัวเลือกแดชบอร์ดของ Payload ที่หน้าภาพรวมแสดงเป็นข้อความธรรมดา |
| กล่องแจ้งผล (toast) | (ปรับ 15 ต.ค. 2569) การ์ดสีขาวมุมโค้ง ขอบซ้ายและไอคอนกลมตามสถานะ: สำเร็จ = เขียว ✓, ผิดพลาด = แดง ✕, เตือน = ส้ม !, ข้อมูล = สีหลัก i; ปุ่มปิดอยู่ด้านขวาในการ์ด ตัวอักษร Prompt (ไม่มีหัว) 14px |
| แถบเมนูตอนย่อ | (เพิ่ม 15 ต.ค. 2569, `NavRail.tsx` + "icon rail" ใน custom.scss) บนจอกว้าง ≥769px กดปุ่ม ‹ แล้วแถบเมนูเหลือแถบแคบ 68px มีแต่ไอคอน กดได้ทุกอัน ชี้แล้วขึ้นชื่อเมนู กลุ่มเมนูคั่นด้วยเส้นบาง (กลุ่มที่พับไว้ก็ยังแสดงไอคอน) ซ่อนชื่อผู้ใช้และหัวกลุ่ม จอเตี้ยเลื่อนแถบไอคอนขึ้นลงได้ด้วยล้อเมาส์หรือปัด (ไม่แสดงแถบเลื่อน; ปุ่ม ☰ มีพื้นสีเข้มให้ไอคอนลอดใต้ได้) กดปุ่ม ☰ เพื่อกางกลับ บนมือถือใช้เมนูเลื่อนออกแบบเดิมของ Payload |
| ตาราง | **แถบสีอ่อนสลับแถว** คอลัมน์สุดท้าย "การทำงาน" เป็นปุ่มไอคอนอย่างเดียว (ปรับ 15 ต.ค. 2569): ดินสอ = "แก้ไข" (สีหลัก), ตา = "ดูบนเว็บ"/"เปิดไฟล์" (เปิดแท็บใหม่), ถังขยะ; ชื่อปุ่มแสดงเป็น tooltip เมื่อชี้ และอ่านได้ด้วยโปรแกรมอ่านหน้าจอ |
| เลื่อนหน้า | (ปรับ 15 ต.ค. 2569, `lists/Pager.tsx`) ใต้ตาราง: ปุ่มหน้าแรก/ก่อนหน้า, เลขหน้า (หน้าแรก หน้าสุดท้าย และ 2 หน้ารอบหน้าปัจจุบัน คั่นด้วย …), ถัดไป/หน้าสุดท้าย, ช่อง "ไปหน้า" (พิมพ์เลขแล้ว Enter) และ "แสดงหน้าละ 25/50/100 รายการ" (`?limit=`; ประวัติการใช้งานตั้งต้น 50, จังหวัด/ประเด็น/ประเภทเอกสาร 100) เหนือตาราง: ตัวย่อ ‹ หน้า x / y › ท้ายบรรทัดจำนวนรายการ บนมือถือซ่อนปุ่มหน้าแรก/สุดท้ายและเลขที่ห่าง 2 หน้าเพื่อให้อยู่บรรทัดเดียว เปลี่ยนตัวกรองหรือการเรียงจะกลับไปหน้า 1 |

- ตัวกรองจังหวัดแสดงเฉพาะผู้ดูแลระบบส่วนกลาง บทบาทระดับจังหวัดเห็นเฉพาะรายการของจังหวัดตัวเองอยู่แล้ว
- ลิงก์ "รายการแบบขั้นสูง" ท้ายหน้าเอกสารและแดชบอร์ดเอาออกแล้ว (15 ต.ค. 2569) หน้ารายการเดิมของ Payload ยังเปิดได้ทาง URL `/admin/collections/<ชื่อ>?advanced=1` เท่านั้น (สิทธิ์ตามบทบาทเหมือนเดิม)
- หน้าภาพรวมลิงก์ไปรายการเอกสารที่กรองตามจังหวัดไว้แล้ว

### 8.15 ประเด็นและรายงานประเด็น

- **เมนู "ประเด็น"** (ผู้ดูแลระบบส่วนกลางแก้ได้): เพิ่ม แก้ชื่อ เลือก**สีประจำประเด็น**โดยกดที่ตัวอย่างสี 13 สี (หรือ "สีเดิม") ใต้ช่องสีมีตัวอย่างป้ายประเด็นตามที่จะแสดงบนหน้าเว็บ ในหน้ารายการประเด็น คอลัมน์ "สี" แสดงเป็นป้ายสีจริง และลำดับการแสดง ประเด็นใหม่เป็นตัวเลือกในฟอร์มเอกสารและแดชบอร์ดทันที สีใช้กับป้ายประเด็นและการ์ดบนหน้าเว็บ
- หน้าแก้ไขประเด็นบอก**จำนวนเอกสารและแดชบอร์ดที่ใช้ประเด็นนี้** (รวมในถังขยะ) พร้อมลิงก์ไปรายการเหล่านั้น
- **ลบ:** ประเด็นที่ยังมีรายการใช้อยู่ลบไม่ได้ ระบบแจ้งให้ย้ายก่อน
- **รวมประเด็น:** "ย้ายรายการไปประเด็นอื่นแล้วลบ" ย้ายเอกสารและแดชบอร์ดทุกรายการ (รวมในถังขยะและเวอร์ชันเก่า) ไปประเด็นที่เลือก แล้วลบประเด็นเดิมในขั้นตอนเดียว (ย้อนกลับไม่ได้ ระบบถามยืนยันก่อน)
- **เมนู "รายงานประเด็น"** (`/admin/topic-report`): ตารางประเด็นทั้งหมดพร้อมจำนวนที่ใช้, **แดชบอร์ดที่ยังไม่มีประเด็น** และชุดข้อมูล/ข้อกำหนดการวิเคราะห์ที่ยังไม่มีประเด็น แต่ละรายการกดไปแก้ไขได้ บทบาทระดับจังหวัดเห็นเฉพาะจังหวัดตัวเอง หน้ารายการแดชบอร์ดเลือกประเด็น "(ยังไม่มีประเด็น)" ได้ด้วย

### 8.16 หน้าแก้ไขและคำอธิบายช่อง

- ฟอร์มเอกสาร แดชบอร์ด เนื้อหากลาง ประกาศ จังหวัด และผู้ใช้ แบ่งเป็น**การ์ดตามส่วน** (เช่น ข้อมูลหลัก, ไฟล์และลิงก์, การแสดงบนเว็บ, ข้อมูลจากเว็บเดิม) ฟอร์มกว้างเต็มพื้นที่ (ไม่เกิน 1180 พิกเซล) ช่อง "ลำดับการแสดง" และ "ปักหมุด" ย้ายจากแถบขวามาไว้ในการ์ด "การแสดงบนเว็บ" ด้านล่าง
- **คำอธิบายช่อง (ⓘ):** ชื่อช่องส่วนใหญ่มีไอคอน ⓘ ชี้เมาส์ (หรือโฟกัสด้วยคีย์บอร์ด) เพื่อดูว่าช่องนั้นคืออะไรและกรอกอย่างไร มีในฟอร์มเอกสาร แดชบอร์ด จังหวัด ผู้ใช้ ประกาศ เนื้อหากลาง ประเด็น และตั้งค่าเว็บไซต์
- ช่องข้อมูลจากเว็บเดิมที่ไม่ได้ใช้แล้วไม่แสดงเป็นคอลัมน์หรือตัวกรอง กล่อง "ข้อมูลจากเว็บเดิม" ในฟอร์มแสดงเฉพาะรายการที่ย้ายมาจากเว็บเดิม (รายการที่สร้างใหม่ไม่เห็น)
- ไม่มีแท็บ "API" (ข้อมูลดิบ JSON) ในหน้าแก้ไขของทุกเมนู หน้าแก้ไขมีเฉพาะ "แก้ไข" และ "เวอร์ชัน" (ถ้ามี)
- **ช่องเลือก/วางไฟล์** (ปรับ 17 ต.ค. 2569): ทุกที่ในหลังบ้านใช้หน้าตาเดียวกัน (กรอบเส้นประ ไอคอนอัปโหลด ปุ่มหลัก บรรทัดบอกชนิดไฟล์ กรอบเปลี่ยนสีเมื่อลากไฟล์มา) และลากไฟล์มาวางได้ทุกที่ ได้แก่ หน้าไฟล์ หน้าต่างอัปโหลดหลายไฟล์ ช่องอัปโหลดในฟอร์ม กรอบภาพ ไฟล์แนบเอกสาร แทนที่ไฟล์ และนำเข้า Excel (`FileDrop.tsx`) หน้าสร้างรายการใหม่มีหัวข้อ "เพิ่ม…ใหม่" แทน "[ไม่มีชื่อ]"
- **หน้าตาการ์ดและฟอร์ม** (ปรับ 16 ต.ค. 2569, สไตล์กลางใน `custom.scss`):
  - การ์ดทุกหน้าของหลังบ้าน (บัญชีของฉัน เพิ่มและนำเข้าผู้ใช้ สถิติการเข้าชม ทำงานต่อ ฯลฯ) และการ์ดตามส่วนในฟอร์มแก้ไข: มุมโค้ง เงาบาง หัวการ์ดเป็นแถบพื้นไล่สีอ่อน มีเส้นสีสั้นนำหน้าหัวข้อและเส้นคั่นใต้หัว (จับหัวการ์ดจากลูกตัวแรกที่มี h2 จึงไม่ต้องแก้ markup ของแต่ละหน้า)
  - หน้า "บัญชีของฉัน" ใช้ไอคอนแทนเส้นสี: กุญแจ (รหัสผ่าน) โทรศัพท์ (2FA) โล่ (รหัสสำรอง)
  - ช่องกรอกในหน้าของเราเอง: มุมโค้ง ชี้แล้วเส้นเข้มขึ้น คลิกแล้วมีวงโฟกัสสีน้ำเงิน ข้อความช่วยใต้ช่องมีไอคอน ⓘ จางนำหน้า
  - ปุ่มหลักสีไล่น้ำเงินเข้ม ชี้แล้วยกขึ้นเล็กน้อย
- **ช่องวันที่ทุกช่อง** (วันที่ประชุม ช่วงเวลาประกาศ โหมดไว้ทุกข์ วันที่ในหน้าผู้ใช้) แสดงเดือนไทยและปี พ.ศ. แบบเดียวกันทั้งหลังบ้าน เช่น "12 ต.ค. 69 - 13.30 น." (ช่องที่ไม่มีเวลา "12 ต.ค. 69") รวมถึงวันเวลาที่ Payload แสดงเอง เช่น "แก้ไขล่าสุดเมื่อ" และหน้าเวอร์ชัน ปฏิทินมีรายชื่อเดือนภาษาไทยและปี พ.ศ. ช่องที่มีเวลาใช้นาฬิกา 24 ชั่วโมง เลือกได้ทีละ 30 นาที ในฐานข้อมูลยังเก็บเป็นวันที่สากลเหมือนเดิม ช่องวันที่เปิดเลือกจากปฏิทินอย่างเดียว พิมพ์เองไม่ได้

## 9. ความปลอดภัยและความเป็นส่วนตัว (สรุป)

- เข้าสู่ระบบ 2 ขั้นทุกบัญชี ช่องทางเข้าระบบด้วยรหัสผ่านอย่างเดียวถูกปิด
- รหัสลับ 2FA เข้ารหัสก่อนเก็บ รหัสสำรองและลิงก์ใช้ครั้งเดียวเก็บเฉพาะค่า hash ไม่ถูกส่งออกทาง API
- ผู้ดูแลตั้งรหัสผ่านแทนผู้อื่นไม่ได้ (ปิดที่ฝั่งเซิร์ฟเวอร์)
- บทบาทระดับจังหวัดเห็นและแก้ได้เฉพาะข้อมูลของจังหวัดตัวเอง (ดูหัวข้อ 7.1) ลบได้แค่ย้ายไปถังขยะ ลบถาวรได้เฉพาะส่วนกลาง (ปิดที่ฝั่งเซิร์ฟเวอร์)
- ผู้เข้าชมทั่วไปเห็นเฉพาะเนื้อหาที่เผยแพร่ และไฟล์เวอร์ชันปัจจุบัน
- หน้าสาธารณะไม่สร้างคุกกี้ระบุตัวตน สถิติการเข้าชมไม่เก็บ IP
- ข้อความนโยบายทั้งสองฉบับเป็น**ร่าง** ต้องให้ฝ่ายกฎหมายหรือเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคลตรวจก่อนเผยแพร่บนระบบจริง
- ระบบยังไม่มีการลบข้อมูลตามระยะเวลาสำหรับ ประวัติการใช้งาน บันทึกความยินยอมคุกกี้ และบัญชีที่เลิกใช้ ถ้านโยบายกำหนดระยะเวลาเก็บ ต้องเพิ่มการลบในระบบให้ตรงกัน
- ทุกคำสั่งแก้ไขผ่าน API ต้องเข้าสู่ระบบ คนที่ไม่ได้เข้าสู่ระบบแก้ตั้งค่าเว็บไซต์หรือเนื้อหาไม่ได้
- **ไฟล์** (15 ต.ค. 2569): บทบาทระดับจังหวัดแก้/แทนที่ได้เฉพาะไฟล์ของจังหวัดตัวเอง อ่านได้เฉพาะไฟล์ฉบับปัจจุบันและเวอร์ชันเก่าของจังหวัดตัวเอง ทั้งทางหน้าจอและ API (`lib/provinceFiles.ts`)
- **ช่องกรอกข้อมูล** ตรวจรูปแบบที่เซิร์ฟเวอร์ด้วยกฎชุดเดียวกับฟอร์ม (`lib/fieldRules.ts`) ทั้งฟอร์มขอใช้บัญชี เพิ่มผู้ใช้ และนำเข้า Excel
- **ฟอร์มขอใช้บัญชี** (หน้าสาธารณะ): ช่องลับดักโปรแกรม ปฏิเสธการส่งเร็วกว่า 3 วินาที ไม่เกิน 20 คำขอที่บันทึกสำเร็จต่อ IP ต่อชั่วโมงบนระบบจริง (IP อ่านจาก `X-Real-IP` ของ nginx ไม่เก็บลงฐานข้อมูล) คำขอถูกลบเมื่อครบ 30 วัน
- การตรวจชื่อผู้ใช้ว่าว่างหรือไม่ (`/api/users/usernames`) ใช้ได้เฉพาะผู้ดูแลส่วนกลางและผู้ดูแลจังหวัด คนนอกไล่เดาชื่อผู้ใช้ไม่ได้
- Google Analytics (เตรียมไว้ ยังปิด) โหลดเฉพาะเมื่อผู้เข้าชมอนุญาตคุกกี้ "สถิติการใช้งาน" ถอนความยินยอมแล้วลบคุกกี้ `_ga`

**ตรวจความปลอดภัย 17 ต.ค. 2569** (ทดสอบกับระบบที่รันจริงบนเครื่องพัฒนา ในฐานะคนนอก ผู้ดูแลจังหวัด และผู้ดูแลส่วนกลาง)
- ผ่าน: เข้าระบบด้วยรหัสผ่านอย่างเดียวผ่านช่องทางของ Payload ไม่ได้ (`/api/users/login`) สร้างผู้ดูแลคนแรกซ้ำไม่ได้ ลืมรหัสผ่านแบบอีเมลปิดอยู่ ข้อมูลผู้ใช้ ลิงก์ใช้ครั้งเดียว ประวัติการใช้งาน คำขอบัญชี สถิติ ความยินยอมคุกกี้ ร่าง ถังขยะ และไฟล์เวอร์ชันเก่า คนนอกอ่านไม่ได้ endpoint สำหรับผู้ดูแลทั้งหมดปฏิเสธคนนอก ผู้ดูแลจังหวัดเห็นเฉพาะผู้ใช้/เอกสาร/ประวัติของจังหวัดตัวเอง รหัสลับ 2FA และรหัสสำรองไม่ออกทาง API รหัส 2FA ผิด 5 ครั้งล็อก 15 นาที ข้อความเมื่อเข้าระบบผิดไม่บอกว่าชื่อผู้ใช้มีอยู่หรือไม่ อัปโหลด SVG/HTML (รวมถึงปลอมนามสกุล) ถูกปฏิเสธ path traversal ใน `/uploads` ไม่ได้ผล ประวัติการใช้งานสร้าง/แก้/ลบผ่าน API ไม่ได้ ไม่มีการต่อ SQL จากข้อความ (ใช้พารามิเตอร์ทั้งหมด) ไม่มีการแสดง HTML จากข้อมูลผู้ใช้
- แก้แล้ว: (1) เพิ่ม security headers ทุกหน้า: `X-Frame-Options: SAMEORIGIN` และ `frame-ancestors 'self'` (กันเอาหน้าหลังบ้านไปซ้อนในเว็บอื่น), `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy` และเอา `X-Powered-By` ออก (`next.config.ts`) (2) คุกกี้เข้าสู่ระบบส่งเฉพาะ HTTPS เมื่อ `SITE_URL` เป็น https:// และ SameSite=Lax (3) รับคุกกี้เฉพาะคำขอจาก `SITE_URL` (Payload `csrf`/`cors`) คำขอจากเว็บอื่นที่แนบคุกกี้ถูกปฏิเสธ (4) ปิด GraphQL และ GraphQL Playground (ไม่ได้ใช้) (5) ระบุชนิดไฟล์ภาพทีละชนิด (JPG PNG GIF WebP) แทน `image/*` (6) ตัวอย่าง nginx: HSTS, ซ่อนเวอร์ชัน, TLS 1.2+, จำกัดคำขอเข้าสู่ระบบ 10 ครั้ง/นาที/IP (กันเดารหัสและกันการจงใจล็อกบัญชี `admin_<จังหวัด>` ที่ชื่อเดาได้)
- ยังค้าง: (1) **อัปเดตแพ็กเกจ** `npm audit` พบช่องโหว่ 15 รายการ (critical 1, high 6) critical คือ Next.js `next/og` ซึ่งระบบไม่ได้ใช้ ควรอัปเดต next → 16.4.2, payload และ @payloadcms/* → 3.91.0, sharp → 0.35.5 แล้วรันชุดทดสอบทั้งหมด (2) ระบบจริงต้องใช้ `PAYLOAD_SECRET` สุ่มยาวอย่างน้อย 32 ตัว (เครื่องพัฒนาใช้ 24 ตัว) (3) ยอดเข้าชม/ดาวน์โหลด (`/hit`, `/visit`) ไม่จำกัดจำนวนครั้งต่อ IP ปั่นตัวเลขได้ (ไม่กระทบข้อมูลอื่น) (4) ผู้ดูแลจังหวัดเห็นรายการ session ของผู้ใช้ในจังหวัด (รหัส session อย่างเดียว ใช้ปลอมตัวไม่ได้) (5) ไฟล์ของเอกสารที่ยังเป็นร่างเปิดได้ถ้ารู้ลิงก์ (ลิงก์มีส่วนสุ่ม เดายาก) (6) รหัส 2FA ใช้ซ้ำได้ภายในช่วง 30 วินาทีเดียวกัน

## 10. สคริปต์ทดสอบอัตโนมัติ

รันจากโฟลเดอร์ `web` ขณะที่เซิร์ฟเวอร์เปิดอยู่ ทุกสคริปต์สร้างข้อมูลทดสอบเองแล้วลบออกเมื่อจบ ผลล่าสุด (16 ต.ค. 2569 หลังเปลี่ยนรหัสผ่านขั้นต่ำเป็น 8 ตัว): ผ่านทั้ง 4 ชุด (`check-auth` มีกรณีรหัส 7 ตัวต้องถูกปฏิเสธ) สคริปต์ลบบรรทัดของตัวเองออกจากประวัติการใช้งานหลังรัน

| คำสั่ง | สิ่งที่ตรวจ |
|---|---|
| `npx payload run scripts/check-versions.ts` | อัปโหลด แทนที่ ประวัติ และกู้คืนไฟล์ / บังคับแนบไฟล์ก่อนเผยแพร่ / ถังขยะ |
| `npx payload run scripts/check-auth.ts` | เข้าสู่ระบบ 2 ขั้น รหัสสำรอง การล็อก ลิงก์ใช้ครั้งเดียว สิทธิ์ 3 บทบาท ระงับบัญชี รีเซ็ต 2FA นำเข้า Excel การแทนที่ไฟล์ผ่าน API บัญชีของฉัน |
| `npx payload run scripts/check-public.ts` | หน้าแผนงานและคู่มือ หน้านโยบาย โหมดไว้ทุกข์ (รวมระดับสีเทา ปิดโหมดเองก่อนเริ่มและคืนค่าเดิมเมื่อจบ) ป๊อปอัป (รวมป๊อปอัปที่มีแค่ภาพ) ตัวนับการเข้าชม บันทึกความยินยอมคุกกี้ |
| `npx payload run scripts/check-extras.ts` | ตัวนับเข้าชม/ดาวน์โหลดรายรายการ ชื่อเอกสารมาตรฐาน ประวัติการใช้งาน ระงับอัตโนมัติ 365 วัน ลบถังขยะ 30 วัน ส่งออก Excel หน้าสถิติและหน้ารอตรวจ ไฟล์ GIF ไม่ถูกแปลง การรวม/ลบประเด็นและรายงานประเด็น สิทธิ์ถังขยะ (จังหวัดย้ายไปถังขยะ/กู้คืนได้ ลบถาวรไม่ได้) |

หน้าจอหลังบ้านตรวจด้วยตาผ่านภาพหน้าจอจาก Chrome แบบไม่มีหน้าต่าง โดยใช้บัญชีชั่วคราว `zz-test-ui` (`scripts/ui-session.ts` เข้าเป็นบทบาทจังหวัดได้ด้วย `UI_ROLE=province_manager UI_PROVINCE=<slug>` ลบด้วย `REMOVE=1` หลังใช้ทุกครั้ง)

การตรวจอื่นที่ทำไว้: หน้าเว็บทั้ง 228 หน้า (76 จังหวัด × 3 หน้า) เปิดได้, ลิงก์ไฟล์แบบเดิมสุ่ม 300 ลิงก์เปิดได้, จำนวนเอกสารรายจังหวัดรายปีตรงกับต้นทางทั้ง 323 ช่อง, `schema.sql` รันผ่านบน PostgreSQL 17

ชุดติดตั้ง (ทดสอบบนเครื่องพัฒนา 12 ต.ค. 2569): สร้างอิมเมจได้, เริ่มระบบบนฐานข้อมูลเปล่าได้ (สร้างตารางเอง ออกลิงก์เปิดใช้บัญชีผู้ดูแลคนแรก), ย้ายเนื้อหาจากฐานข้อมูลพัฒนาเข้าไปแล้วได้จำนวนตรงกัน (76 / 2,968 / 559 / 2,902 / 20) และเปิดหน้าจังหวัดได้ ไฟล์เอกสารทดสอบคัดลอกเพียง 1 ไฟล์ ยังไม่ได้ลองคัดลอกทั้ง 4.2 GB

## 11. โครงสร้างข้อมูลในระบบ

| ชุดข้อมูล | เก็บอะไร |
|---|---|
| เอกสาร (documents) | จังหวัด ปีงบประมาณ ประเภท ประเด็น ชื่อ คำอธิบาย ประเด็นการพัฒนา ครั้งที่ วันที่ประชุม ไฟล์แนบ ลิงก์ภายนอก สถานะร่าง/เผยแพร่ ข้อมูลจากเว็บเดิม |
| แดชบอร์ด (dashboards) | จังหวัด ปี ประเด็น ชื่อ ผู้ให้บริการ ลิงก์ฝัง ภาพตัวอย่าง เอกสารประกอบ ปักหมุด ลำดับการแสดง |
| ไฟล์ (files) | ไฟล์จริง ชื่อเดิม sha256 ลิงก์ถาวร เวอร์ชัน เหตุผลที่แก้ ผู้อัปโหลด ยอดดาวน์โหลด |
| เนื้อหากลาง (central-contents) | หมวด ปี หัวข้อ เนื้อหา ที่มา ไฟล์ รายการลิงก์ |
| ประกาศ (announcements) | ดูหัวข้อ 8.9 |
| จังหวัด (provinces) | slug รหัสย่อ ชื่อ ลิงก์ CKAN ข้อมูลสำนักงาน ธีม ภาพเด่น |
| ประเด็น (topics) | ชื่อ สีประจำประเด็น ลำดับการแสดง |
| ประเภทเอกสาร (document-types) | ชื่อ หัวข้อบนหน้าเว็บ ต้องระบุครั้งที่/ประเด็นหรือไม่ |
| ผู้ใช้ (users) | ชื่อผู้ใช้ ชื่อ ชื่อภาษาอังกฤษ ตำแหน่ง โทรศัพท์ อีเมล บทบาท จังหวัดที่ดูแล สถานะ ข้อมูล 2FA |
| คำขอบัญชี (account-requests) | ชื่อ ชื่อภาษาอังกฤษ จังหวัด ตำแหน่ง หน่วยงาน โทรศัพท์ อีเมล เหตุผล สถานะ ผู้พิจารณา วันพิจารณา บัญชีที่สร้าง (ลบเองเมื่อครบ 30 วัน) |
| ตั้งค่าเว็บไซต์ (site-settings) | โหมดไว้ทุกข์ (รวมระดับสีเทา) ส่วนท้าย นโยบาย Google Analytics |
| ประวัติการใช้งาน (activity-logs) | ผู้ใช้ การกระทำ ส่วนของระบบ รายการ จังหวัด วันเวลา |
| ยอดเข้าชมรายวัน / ยอดเข้าชมและดาวน์โหลดรายรายการ (hit-counts) / บันทึกความยินยอมคุกกี้ / ลิงก์ใช้ครั้งเดียว | ข้อมูลระบบ ไม่แสดงในเมนู |

`migration/schema.sql` เป็นแบบอ้างอิงเชิงออกแบบ ตารางจริงสร้างโดย Payload จากไฟล์ใน `web/src/collections/` และบางตารางในแบบอ้างอิงยังไม่ได้ทำในระบบจริง

## 14. สิ่งที่ยังไม่ได้ทำ

**รอข้อมูลหรือการตัดสินใจ**

- แดชบอร์ด 3 รายการลิงก์ Power BI เสีย จึงไม่มีภาพหน้าปก (#223, #291, #330 ดูหัวข้อ 6.3) ต้องให้จังหวัดแก้ลิงก์
- ข้อความนโยบายฉบับจริง (ตอนนี้เป็นร่าง รอเติมข้อมูลและตรวจ) และยังไม่ได้ใส่บนระบบจริง ร่างนโยบายคุกกี้ใน `docs/policy/` ปรับเรื่องการเก็บตัวเลือกแยกรายจังหวัดแล้ว แต่ยังไม่ได้ใส่ฉบับปรับนี้ลงหน้านโยบายบนเครื่องพัฒนา

- ก่อนเปิด Google Analytics: แก้นโยบายคุกกี้ข้อ 3 ตาม `docs/policy/cookie-policy-draft.txt` และเพิ่มเลขเวอร์ชันนโยบาย
- นโยบายความเป็นส่วนตัว: เพิ่มเรื่องการเก็บข้อมูลผู้ขอบัญชี (ชื่อ ติดต่อ) ไม่เกิน 30 วัน

**ข้อจำกัดที่ทราบ**
- หน้านโยบายรองรับเฉพาะข้อความล้วน หัวข้อตัวหนา และการขึ้นบรรทัด ยังไม่รองรับตาราง ลิงก์ หรือตัวหนากลางประโยค

- ตัวช่วยตั้งชื่อเอกสาร และเครื่องมือเลือกจุดเด่นของภาพ ตรวจด้วยสคริปต์ว่าทำงานถูก แต่ยังไม่ได้ลองใช้จริงโดยเจ้าหน้าที่
- โหมดมืด: ตรวจครบ 8 ธีม × 4 หน้า (หน้าหลัก เอกสาร สารสนเทศ แผนงานและคู่มือ) เมื่อ 15 ต.ค. 2569 ด้วยสคริปต์วัดความต่างสีข้อความกับพื้นตามเกณฑ์ WCAG (4.5:1 ตัวอักษรปกติ, 3:1 ตัวใหญ่) ผ่านทุกข้อความ และดูภาพหน้าจอประกอบ ยกเว้นข้อความบนภาพเด่นที่วัดด้วยสคริปต์ไม่ได้ (ดูด้วยตาแล้วอ่านได้) แถบคุกกี้และป๊อปอัปในโหมดมืดยังไม่ได้วัดรอบนี้
- ยังไม่ได้ทดสอบบนโทรศัพท์จริง
- ไฟล์: บทบาทระดับจังหวัดอ่านข้อมูลไฟล์ฉบับปัจจุบันของจังหวัดอื่นผ่าน API ได้ (เท่ากับที่ผู้เข้าชมทั่วไปเปิดได้จากหน้าเว็บ) แต่แก้ไม่ได้
- เพดานคำขอบัญชี 20 ครั้ง/ชั่วโมง ทำงานเฉพาะบนระบบจริง ยังไม่ได้ทดสอบตอนเปิดใช้งาน (ทดสอบตอนติดตั้ง: ส่งคำขอถูกต้อง 21 ครั้งจากเครื่องเดียว ครั้งที่ 21 ต้องถูกปฏิเสธ)
