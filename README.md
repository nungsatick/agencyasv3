# ระบบสนับสนุนการจัดทำบัญชีข้อมูลจังหวัด

เว็บไซต์ใหม่ที่ **https://newagencyas.gdcatalog.go.th** แทนที่เว็บเดิม agencyas.gdcatalog.go.th (PHP) ของ 76 จังหวัด
รองรับ path เดิมทั้งหมด ลิงก์เดิมมาถึงเว็บใหม่ได้เมื่อโดเมนเดิมส่งต่อ (301) มา

> **สถานะ (19 ต.ค. 2569):** รันได้ครบบนเครื่องพัฒนาด้วยข้อมูลจริง 76 จังหวัด มีชุดติดตั้งและคู่มือแล้ว ยังไม่ได้ติดตั้งบนเซิร์ฟเวอร์จริง
> ก่อนติดตั้งต้องอัปเดตแพ็กเกจตามผลตรวจความปลอดภัย (ดู [SYSTEM_SUMMARY ข้อ 9](docs/SYSTEM_SUMMARY.md))

รายละเอียดทั้งหมดอยู่ใน [docs/SYSTEM_SUMMARY.md](docs/SYSTEM_SUMMARY.md) งานแต่ละวันอยู่ใน [docs/CHANGELOG.md](docs/CHANGELOG.md)

## ระบบมีอะไรบ้าง

**หน้าเว็บสาธารณะ** ของแต่ละจังหวัด (`/{จังหวัด}`)
- หน้าหลัก: ภาพเด่น ตัวเลขสรุป แดชบอร์ดแนะนำ และเอกสารล่าสุด
- เอกสาร (`/docs`): รายงานการประชุม ชุดข้อมูลตามประเด็น ข้อกำหนดการวิเคราะห์ กรองตามปีงบ ดูตัวอย่างไฟล์ในหน้า
- สารสนเทศเพื่อการตัดสินใจ (`/utilization`): แดชบอร์ด Power BI ตามประเด็น
- แผนงานและคู่มือ (`/guides`): เนื้อหากลางที่เหมือนกันทุกจังหวัด
- ธีมสี 8 ชุด โหมดมืด ปรับขนาดตัวอักษร ประกาศป๊อปอัป โหมดไว้ทุกข์ ขอความยินยอมคุกกี้ และฟอร์มขอใช้บัญชีเจ้าหน้าที่

**ระบบหลังบ้าน** (`/admin`)
- ภาพรวม 76 จังหวัด จัดการเอกสาร แดชบอร์ด ไฟล์ (มีประวัติเวอร์ชันและกู้คืนได้) ถังขยะ 30 วัน
- เนื้อหากลาง ประกาศ ตั้งค่าเว็บไซต์ (เฉพาะผู้ดูแลส่วนกลาง)
- ผู้ใช้ 3 บทบาท (ส่วนกลาง / ผู้ดูแลจังหวัด / เจ้าหน้าที่จังหวัด) บทบาทจังหวัดเห็นและแก้ได้เฉพาะจังหวัดตัวเอง
- เพิ่มและนำเข้าผู้ใช้จาก Excel คำขอบัญชี ประวัติการใช้งาน
- สถิติการเข้าชมพร้อมแผนที่ประเทศไทย รายงานประเด็น รายการรอตรวจ

**ความปลอดภัย**
- เข้าสู่ระบบด้วยชื่อผู้ใช้ รหัสผ่าน (อย่างน้อย 8 ตัว) และรหัส 2FA จากแอป ทุกบัญชี
- ระบบไม่ส่งอีเมลเอง (ไม่มี mail server) บัญชีใหม่และลืมรหัสผ่านใช้ลิงก์ใช้ครั้งเดียวที่ผู้ดูแลส่งให้
- ตรวจความปลอดภัยทั้งระบบแล้ว 17 ต.ค. 2569 (security headers, กัน CSRF, คุกกี้ HTTPS-only, จำกัดการเดารหัส)

## เทคโนโลยี

Next.js 16 (App Router) + Payload CMS 3 + PostgreSQL 17 เป็นแอปเดียวในโฟลเดอร์ `web/`
ติดตั้งบนเซิร์ฟเวอร์ด้วย Docker Compose หลัง nginx

## โครงสร้างโฟลเดอร์

| โฟลเดอร์ | เนื้อหา |
|---|---|
| `web/` | แอปหลัก (หน้าเว็บ + หลังบ้าน) |
| `web/src/collections/` | โครงสร้างข้อมูลและสิทธิ์ของแต่ละตาราง |

| `web/src/components/admin/` | หน้าจอหลังบ้านที่สร้างเพิ่ม |
| `web/src/migrations/` | migration ฐานข้อมูล ระบบรันเองตอนเริ่ม |
| `web/scripts/` | สคริปต์นำเข้าข้อมูล โหลดข้อมูลตั้งต้น และชุดทดสอบ |
| `web/public/logos/` | ตราจังหวัด 76 ไฟล์ (`{CODE}.png`) |
| `deploy/` | ชุดติดตั้งบนเซิร์ฟเวอร์ (Docker Compose, nginx, สคริปต์สำรองข้อมูล, `.env.example`) |
| `migration/` | ข้อมูลจากเว็บเดิมที่จับคู่เข้าโครงสร้างใหม่ (`import/*.json`), `manifest.json` (sha256 ของไฟล์เดิม), บัญชีผู้ดูแลจังหวัด 76 บัญชี และสคริปต์สร้างข้อมูล |
| `crawl/` | ผลสำรวจเว็บเดิม (`sites.json`) |

| `assets/logos/` | โลโก้หน่วยงาน (ต้นฉบับ) |

## เปิดระบบบนเครื่องพัฒนา

ต้องมี Node.js และ Docker Desktop

```bash
docker compose up -d db
```

```bash
npm --prefix web install
```

```bash
npm --prefix web run dev
```

จากนั้นเปิด http://localhost:3000/sisaket (หน้าเว็บ) หรือ http://localhost:3000/admin (หลังบ้าน)

- ฐานข้อมูลพัฒนาอยู่ที่พอร์ต 5433 รหัสผ่านใน `docker-compose.yml` ใช้บนเครื่องพัฒนาเท่านั้น
- เครื่องใหม่ที่ฐานข้อมูลยังว่าง: สร้าง `web/.env` จาก `web/.env.example` แล้วนำเข้าข้อมูลเดิมด้วย `npx payload run scripts/import.ts` ในโฟลเดอร์ `web` (ต้องมี `migration/files/`) ขั้นตอนต่อจากนั้นอยู่ใน SYSTEM_SUMMARY ข้อ 4
- ถ้าเปลี่ยนโครงสร้างข้อมูล ให้สร้าง migration ด้วย `npx payload migrate:create <ชื่อ>` แล้วตามด้วย `npx payload generate:types` และเพิ่มชื่อ migration ในรายการที่ต้องรันใน CHANGELOG

## ทดสอบ

รันในโฟลเดอร์ `web` ขณะที่เซิร์ฟเวอร์พัฒนาเปิดอยู่ ทุกชุดสร้างข้อมูลทดสอบเองและลบออกเมื่อจบ

```bash
npx payload run scripts/check-auth.ts
```

| ชุด | ตรวจอะไร |
|---|---|
| `check-auth.ts` | เข้าสู่ระบบ 2 ขั้น สิทธิ์ 3 บทบาท การจำกัดจังหวัด ลิงก์ใช้ครั้งเดียว นำเข้า Excel |
| `check-public.ts` | หน้าเว็บสาธารณะ นโยบาย โหมดไว้ทุกข์ ป๊อปอัป ตัวนับการเข้าชม คุกกี้ |
| `check-extras.ts` | ตัวนับเข้าชม/ดาวน์โหลด (รวมเอกสารส่วนกลาง) ชื่อมาตรฐาน ประวัติการใช้งาน ระงับอัตโนมัติ ถังขยะ ส่งออก Excel |
| `check-versions.ts` | อัปโหลด แทนที่ ประวัติ และกู้คืนไฟล์ บังคับแนบไฟล์ก่อนเผยแพร่ |

รายละเอียดอยู่ใน SYSTEM_SUMMARY ข้อ 10
